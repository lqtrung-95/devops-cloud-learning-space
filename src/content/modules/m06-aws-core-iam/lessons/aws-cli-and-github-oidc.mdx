<Eli5 title="OIDC giống như gửi xe bằng vé có tên, thay vì đưa chìa khoá nhà" emoji="🎟️">
  Cách cũ để CI/CD vào AWS là **đưa hẳn một chiếc chìa khoá** (access key) cho GitHub cất giữ. Chìa không hết hạn; ai sao chép được là vào nhà bạn bao lâu cũng được.

  Cách mới dùng **vé gửi xe có tên**: mỗi lần chạy, GitHub in một **vé ngắn hạn** ghi rõ "xe của repo `trung/devops-app`, nhánh `main`". Bảo vệ AWS (**STS**) kiểm tra con dấu của GitHub trên vé và đối chiếu với **danh sách xe được phép** (trust policy).

  Khớp thì bảo vệ đưa một **thẻ tạm dùng trong 1 giờ**. Hết giờ, thẻ vô dụng — lộ ra cũng không sao mấy.

  Còn trên laptop, bạn cũng làm y như vậy với **IAM Identity Center**: đăng nhập SSO, nhận credential tạm, không có key nào nằm lâu dài trong máy.
</Eli5>

## Vì sao DevOps cần hiểu điều này?

"Không có credential dài hạn" là tiêu chuẩn bảo mật mà nhà tuyển dụng DevOps sẽ hỏi. Bạn sẽ dùng **AWS CLI** mỗi ngày, và mọi pipeline ở các module sau (Terraform ở M10, deploy ECS/EKS) đều đi qua **OIDC role** thay vì `AWS_ACCESS_KEY_ID` trong GitHub Secrets.

### AWS CLI v2: profile & SSO

`aws configure sso` sinh cấu hình dạng này:

```ini title="~/.aws/config"
[sso-session my-sso]
sso_start_url = https://d-1234567890.awsapps.com/start
sso_region = ap-southeast-1
sso_registration_scopes = sso:account:access

[profile dev-admin]
sso_session = my-sso
sso_account_id = 123456789012
sso_role_name = AdministratorAccess
region = ap-southeast-1
output = json

[profile prod-readonly]
sso_session = my-sso
sso_account_id = 210987654321
sso_role_name = ReadOnlyAccess
region = ap-southeast-1
```

- Chọn profile: `--profile dev-admin` hoặc `export AWS_PROFILE=dev-admin`.
- CLI tìm credential theo thứ tự ưu tiên (rút gọn): tham số dòng lệnh → biến môi trường (`AWS_ACCESS_KEY_ID`…) → profile trong `~/.aws/config`/`credentials` (SSO, assume role, web identity…) → credential của container/EC2 instance profile.
- Luôn chạy `aws sts get-caller-identity` khi nghi ngờ "mình đang là ai" — lệnh này **không cần quyền IAM nào**.

### GitHub Actions → AWS bằng OIDC

**Bước 1 — OIDC provider** (một lần mỗi account): URL `https://token.actions.githubusercontent.com`, audience `sts.amazonaws.com`. (AWS CLI mới không còn bắt buộc thumbprint cho provider này — kiểm tra tài liệu hiện hành.)

**Bước 2 — Role với trust policy khoá chặt repo và nhánh:**

```json title="github-deploy-trust.json"
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": {
        "Federated": "arn:aws:iam::123456789012:oidc-provider/token.actions.githubusercontent.com"
      },
      "Action": "sts:AssumeRoleWithWebIdentity",
      "Condition": {
        "StringEquals": {
          "token.actions.githubusercontent.com:aud": "sts.amazonaws.com",
          "token.actions.githubusercontent.com:sub": "repo:trung/devops-app:ref:refs/heads/main"
        }
      }
    }
  ]
}
```

Một số giá trị `sub` thường gặp: `repo:ORG/REPO:ref:refs/heads/main` (push nhánh), `repo:ORG/REPO:pull_request`, `repo:ORG/REPO:environment:production` (job dùng GitHub Environment).

**Bước 3 — Workflow:**

```yaml title=".github/workflows/deploy.yml"
name: deploy
on:
  push:
    branches: [main]

permissions:
  id-token: write   # cho phép xin OIDC token
  contents: read

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: aws-actions/configure-aws-credentials@v4   # kiểm tra version mới nhất
        with:
          role-to-assume: arn:aws:iam::123456789012:role/github-deploy
          aws-region: ap-southeast-1
      - run: aws sts get-caller-identity
      - run: aws s3 sync ./site s3://trung-lab-bucket
```

<Callout type="mistake" title="Trust policy quá rộng">
  Dùng `StringLike` với `"repo:trung/*"` cho role deploy prod → mọi repo, mọi nhánh của bạn đều deploy được. Tệ hơn, bỏ hẳn điều kiện `sub` → về lý thuyết workflow của **bất kỳ ai trên GitHub** cũng assume được role (IAM hiện có kiểm tra chặn một số trust policy quá lỏng, nhưng đừng dựa vào đó). Luôn khoá tới repo + nhánh/environment cụ thể và luôn kiểm tra `aud`.
</Callout>

<Callout type="warning">
  Nếu vẫn còn `AWS_ACCESS_KEY_ID` trong GitHub Secrets sau khi chuyển sang OIDC: **deactivate rồi xoá key** đó trong IAM, và xoá secret. Key "dự phòng" chính là key bị lộ trong tương lai.
</Callout>

<Callout type="tip">
  Lỗi `Could not load credentials from any providers` trong workflow gần như luôn do **thiếu `permissions: id-token: write`**. Còn `Not authorized to perform sts:AssumeRoleWithWebIdentity` là do `sub`/`aud` không khớp trust policy.
</Callout>
