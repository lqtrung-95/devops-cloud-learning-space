<Eli5 title="Access token là vé xem phim, refresh token là thẻ thành viên rạp" emoji="🎟️">
  Bạn mua **vé xem phim** (access token): soát vé chỉ liếc qua, không gọi điện hỏi rạp gốc — vé có ngày giờ in sẵn, hết giờ là hết hiệu lực, không ai kiểm tra thêm gì.

  Nhưng để mua vé mới mỗi lần, bạn cần xuất trình **thẻ thành viên** (refresh token) — thẻ này rạp lưu trong hệ thống của họ, và nếu bạn báo mất thẻ, họ khoá nó ngay lập tức trong hệ thống, không ai dùng thẻ đó mua vé được nữa dù thẻ vật lý còn cầm trên tay.
</Eli5>

Đây là lý do `taskflow-api` dùng **hai loại token khác nhau** thay vì một session dài hạn duy nhất: access token nhanh nhưng không revoke được, refresh token revoke được nhưng không dùng trực tiếp để gọi API.

### JWT access token: ký, không mã hoá

JWT (JSON Web Token) gồm 3 phần nối bằng dấu chấm: `header.payload.signature`. Header và payload chỉ **base64url-encode**, ai cũng decode đọc được. Chỉ `signature` là bằng chứng "server đã ký cái này, chưa ai sửa".

```ts title="src/plugins/jwt.ts"
import fastifyJwt from "@fastify/jwt";
import fp from "fastify-plugin";
import { env } from "../lib/env.js";

export default fp(async (app) => {
  app.register(fastifyJwt, {
    secret: env.JWT_ACCESS_SECRET, // KHÔNG commit secret này vào git
    sign: { expiresIn: "15m" },
  });

  app.decorate("authenticate", async (request, reply) => {
    try {
      await request.jwtVerify(); // kiểm tra chữ ký + exp trong một lần gọi
    } catch {
      reply.code(401).send({ error: { code: "UNAUTHORIZED", message: "Token không hợp lệ hoặc đã hết hạn" } });
    }
  });
});
```

Payload chỉ nên chứa dữ liệu **định danh, không nhạy cảm**, vì bất kỳ ai cầm token đều đọc được:

```json title="access token payload (đã decode)"
{ "sub": "3f9e2b1a-...-c8d4", "iat": 1717000000, "exp": 1717000900 }
```

### Refresh token: opaque, hash, lưu DB

Refresh token **không phải JWT** — chỉ là một chuỗi ngẫu nhiên (opaque string), không mang thông tin gì bên trong. Server phải tra DB để biết nó thuộc về ai và còn hiệu lực không.

```ts title="src/routes/auth.ts"
import { randomBytes, createHash } from "node:crypto";

function generateRefreshToken() {
  const raw = randomBytes(32).toString("base64url"); // 256 bit entropy — không thể đoán
  const tokenHash = createHash("sha256").update(raw).digest("hex");
  return { raw, tokenHash }; // raw trả cho client, tokenHash mới lưu DB
}
```

Bảng `refresh_tokens` (thiết kế riêng cho module này, không có trong bảng domain model cố định của mục 3 curriculum):

```ts title="src/db/schema.ts"
export const refreshTokens = pgTable("refresh_tokens", {
  id: uuid("id").primaryKey().defaultRandom(),
  userId: uuid("user_id").notNull().references(() => users.id),
  tokenHash: text("token_hash").notNull(),
  expiresAt: timestamp("expires_at", { withTimezone: true }).notNull(),
  revokedAt: timestamp("revoked_at", { withTimezone: true }),
  createdAt: timestamp("created_at", { withTimezone: true }).notNull().defaultNow(),
});
```

Chỉ lưu `tokenHash` — giống hệt nguyên tắc lưu mật khẩu, và cũng là cách chính hệ thống magic-link login của Learning Space lưu token (`storeToken: "hashed"`): nếu DB rò rỉ, kẻ tấn công có hash chứ không có chuỗi thật để dùng lại.

### Vì sao hai loại token, không phải một

| Lựa chọn | Ưu | Nhược | Dùng khi |
|---|---|---|---|
| Chỉ dùng session dài hạn trong DB | Revoke được ngay lập tức | Mỗi request đều phải query DB — chậm hơn ở quy mô lớn | App nhỏ, ít traffic, ưu tiên đơn giản |
| Chỉ dùng JWT dài hạn (vd 7 ngày), không refresh token | Nhanh, không cần query DB | Không revoke được — nếu token lộ, kẻ tấn công dùng được tới khi hết hạn | Hầu như không nên dùng cho hệ thống thật |
| Access token ngắn (JWT) + refresh token dài (DB) | Verify nhanh (JWT) + revoke được (refresh) — cân bằng cả hai | Phức tạp hơn: cần endpoint `/refresh`, cần bảng riêng | `taskflow-api` và phần lớn hệ thống production |

<Callout type="warning" title="Không nhét dữ liệu nhạy cảm vào JWT">
  JWT chỉ ký, không mã hoá — mọi client (và bất kỳ ai chặn được request) đều đọc được payload. Không bao giờ đặt mật khẩu, số thẻ, hay quyền hạn chi tiết cần giữ bí mật vào payload JWT.
</Callout>

<Callout type="mistake">
  Dùng cùng một secret cho access token và cho việc ký thứ khác (ví dụ webhook signature). Nếu secret đó lộ ở một chỗ, mọi thứ dùng chung secret đều bị ảnh hưởng — mỗi mục đích nên có secret riêng.
</Callout>
