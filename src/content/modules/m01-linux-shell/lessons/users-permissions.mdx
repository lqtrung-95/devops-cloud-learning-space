  Trong chung cư, mỗi phòng có **chủ phòng**, **người trong gia đình**, và **khách lạ**.

<Technical>

### User & group

- Mỗi người/chương trình chạy dưới một **user** có UID riêng. Danh sách nằm trong `/etc/passwd`.
- **Group** gom nhiều user lại để cấp quyền chung (ví dụ group `docker`, `sudo`, `devops`).
- **root** (UID 0) bỏ qua mọi kiểm tra quyền.

### Đọc quyền trong `ls -l`

```text
-rwxr-x---  1  trung  devops  1204  Sep 13 09:00  deploy.sh
│└┬┘└┬┘└┬┘      │      │
│ │  │  │       owner  group
│ │  │  └── others: ---  (không gì)
│ │  └───── group:  r-x  (đọc, chạy)
│ └──────── owner:  rwx  (đọc, sửa, chạy)
└────────── loại: - file, d thư mục, l symlink
```

Với **thư mục**, ý nghĩa hơi khác: `r` = xem danh sách file bên trong, `w` = tạo/xoá file bên trong, `x` = được "bước vào" (`cd`).

### chmod: hai cách viết

| Kiểu số (octal) | Kiểu chữ (symbolic) | Ý nghĩa |
|---|---|---|
| `chmod 644 file` | `chmod u=rw,go=r file` | File thường: chủ sửa, người khác chỉ đọc |
| `chmod 755 script.sh` | `chmod u=rwx,go=rx script.sh` | Script/thư mục ai cũng chạy được |
| `chmod 600 id_ed25519` | `chmod u=rw,go= id_ed25519` | File bí mật: chỉ chủ đọc/sửa |
| — | `chmod +x script.sh` | Thêm quyền chạy cho mọi người |

### sudo & nguyên tắc least privilege

`sudo` = "mượn chìa khoá vạn năng cho **một lệnh này thôi**", và mọi lần mượn đều được ghi log. Đó là lý do ta làm việc bằng user thường + `sudo` khi cần, thay vì đăng nhập thẳng root.

**Least privilege** (quyền tối thiểu): mỗi user, mỗi app chỉ có đúng quyền nó cần. Nguyên tắc này sẽ quay lại ở AWS IAM, Kubernetes RBAC… — học một lần, dùng cả đời.

</Technical>

<Callout type="mistake">
  **`chmod 777` để "cho chạy được".** Đây là mở toang cửa cho mọi người sửa file — kể cả kẻ tấn công đã lọt vào qua một app khác. Hãy tìm xem **ai** cần quyền **gì**, rồi cấp đúng chừng đó.
</Callout>

<Callout type="warning">
  SSH sẽ **từ chối** dùng private key nếu file có quyền quá rộng. Luôn đặt `chmod 700 ~/.ssh` và `chmod 600 ~/.ssh/id_ed25519`.
</Callout>
