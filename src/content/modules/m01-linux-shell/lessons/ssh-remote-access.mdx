  SSH key thì khác. Bạn có **một con dấu riêng** (private key) cất trong túi, và gửi **mẫu dấu** (public key) cho ngân hàng (server).

<Technical>

**SSH (Secure Shell)** tạo một kết nối được mã hoá tới máy khác (mặc định cổng **22**) để chạy lệnh, copy file, hoặc làm "đường hầm".

### Public-key authentication

1. `ssh-keygen` sinh **cặp khoá bất đối xứng**: private key và public key liên quan toán học với nhau.
2. Public key được thêm vào `~/.ssh/authorized_keys` của user trên server.
3. Khi kết nối, server gửi dữ liệu thách thức; client **ký** bằng private key; server **xác minh chữ ký** bằng public key.

Khuyến nghị dùng thuật toán **Ed25519** (khoá ngắn, nhanh, an toàn). Có thể đặt **passphrase** cho private key, và dùng `ssh-agent` để không phải gõ lại liên tục.

### Cấu hình giúp gõ ít hơn

```text title="~/.ssh/config"
Host lab
  HostName 203.0.113.10
  User trung
  IdentityFile ~/.ssh/id_ed25519

Host web-private
  HostName 10.0.2.15
  User ubuntu
  ProxyJump lab        # đi qua máy "lab" để vào máy trong mạng riêng
```

Giờ chỉ cần gõ `ssh lab` hoặc `ssh web-private`.

### Làm cứng (hardening) SSH server

Trong `/etc/ssh/sshd_config`:

```text
PasswordAuthentication no   # chỉ cho đăng nhập bằng key
PermitRootLogin no          # không cho SSH thẳng vào root
```

Rồi `sudo sshd -t` (kiểm tra cú pháp) và `sudo systemctl reload ssh`.

</Technical>

<Callout type="warning" title="Đừng tự khoá mình ở ngoài">
  Trước khi đặt `PasswordAuthentication no`, hãy **mở một terminal thứ hai** và thử SSH bằng key thành công. Giữ phiên cũ mở cho tới khi chắc chắn — nếu cấu hình sai, bạn vẫn còn đường sửa.
</Callout>

<Callout type="mistake">
  Commit private key vào Git, hoặc copy private key lên server "cho tiện". Nếu lỡ lộ: **tạo cặp khoá mới** và xoá public key cũ khỏi mọi `authorized_keys` ngay lập tức.
</Callout>

<Callout type="info" title="Xem trước tương lai">
  Trên AWS bạn sẽ học **SSM Session Manager** — vào server mà **không cần mở cổng 22** chút nào. Nhưng SSH vẫn là kỹ năng nền tảng bạn dùng hằng ngày (và cũng là cách Git nói chuyện với GitHub).
</Callout>
