<Eli5 title="Request đi qua dây chuyền trạm kiểm soát ở sân bay" emoji="🛂">
  Trước khi lên máy bay, hành lý và hành khách đi qua nhiều trạm: soi chiếu an ninh, kiểm tra vé, kiểm tra hộ chiếu, rồi mới tới cửa lên máy bay. Mỗi trạm chỉ làm đúng một việc, và trạm sau chỉ chạy khi trạm trước cho qua.

  **Hook** trong Fastify chính là các trạm đó. Request của client đi qua `onRequest` (vừa vào cổng), `preValidation` (kiểm tra giấy tờ trước khi soát vé), `preHandler` (trạm cuối trước khi vào máy bay), rồi mới tới `handler` (máy bay thật sự cất cánh — code route của bạn chạy), và `onSend` (kiểm tra hành lý lần cuối trước khi đóng cửa khoang).

  Lợi ích: logic dùng chung (log, đo thời gian, sau này là auth) đặt ở đúng trạm, không phải copy-paste vào từng route.
</Eli5>

### Vì sao không viết logic chung ngay trong handler?

Nếu copy đoạn "log request + đo thời gian" vào đầu mỗi route handler, thêm 1 route mới là thêm 1 chỗ dễ quên. Hook giải quyết đúng vấn đề này: đăng ký một lần, chạy cho **mọi** route trong phạm vi nó được đăng ký (root app = mọi route, một plugin = chỉ route trong plugin đó).

### Viết hook log request bằng `onRequest` + `onResponse`

```ts title="src/plugins/request-logger.ts"
import fp from "fastify-plugin";
import type { FastifyInstance, FastifyRequest } from "fastify";

// Module augmentation: khai báo thêm field cho FastifyRequest để TypeScript không báo lỗi.
declare module "fastify" {
  interface FastifyRequest {
    startTime?: bigint;
  }
}

async function requestLoggerPlugin(fastify: FastifyInstance) {
  fastify.addHook("onRequest", async (request: FastifyRequest) => {
    request.startTime = process.hrtime.bigint();
  });

  fastify.addHook("onResponse", async (request, reply) => {
    const durationMs = request.startTime ? Number(process.hrtime.bigint() - request.startTime) / 1_000_000 : undefined;
    request.log.info({ method: request.method, url: request.url, statusCode: reply.statusCode, durationMs }, "request completed");
  });
}

// fp() vì hook này cần áp dụng cho MỌI route ở mọi plugin, không chỉ context của chính nó.
export const requestLogger = fp(requestLoggerPlugin);
```

```ts title="src/app.ts (đăng ký ở root, trước các route plugin)"
app.register(requestLogger);
app.register(projectRoutes, { prefix: "/api/v1/projects" });
app.register(taskRoutes, { prefix: "/api/v1" });
```

### 5 hook chính và việc điển hình đặt ở mỗi hook

| Hook | Khi nào chạy | Việc điển hình |
|---|---|---|
| `onRequest` | Ngay khi request tới, chưa parse body | Gắn `requestId`, bắt đầu đếm thời gian |
| `preValidation` | Trước khi Fastify validate schema | Chuẩn hoá payload trước khi validate (ví dụ trim string) |
| `preHandler` | Sau validate, trước khi vào route handler | Kiểm tra quyền hạn — B06 sẽ thêm `requireRole` đúng ở đây |
| *(handler)* | Route logic của bạn | Đọc/ghi `store`, trả response |
| `onResponse` | Ngay sau khi response đã gửi xong | Log kết quả, đo latency — không chặn client chờ |

`onSend` (trước `onResponse`, khi payload đã serialize nhưng chưa gửi ra network) cũng hợp lệ để log, nhưng `onResponse` an toàn hơn cho việc đo thời gian vì nó chắc chắn chạy SAU khi response đã rời đi — không góp phần vào latency mà client cảm nhận được.

<Callout type="warning" title="Đừng để hook throw lỗi im lặng">
  Nếu hook `onRequest`/`preHandler` throw exception mà không được xử lý, Fastify sẽ trả lỗi cho TOÀN BỘ request đi qua hook đó — kể cả những route không liên quan tới logic bạn vừa thêm. Luôn bọc logic hook trong `try/catch` nếu nó có khả năng lỗi (ví dụ parse JSON thủ công), và test riêng hook đó trước khi đăng ký ở root.
</Callout>

<Callout type="tip">
  Thứ tự `app.register()` quan trọng: đăng ký `requestLogger` TRƯỚC các route plugin để hook có hiệu lực với mọi route đăng ký sau đó. Đăng ký sau thì các route đã đăng ký trước sẽ không có hook.
</Callout>
