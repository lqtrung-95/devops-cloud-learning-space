`taskflow-api` từ B05 dùng cookie `httpOnly` để lưu refresh token. Đây là chi tiết quan trọng: một khi có cookie, cấu hình CORS sai một chút là mở đường cho site lạ mượn cookie của người dùng để gọi API thay họ.

<Technical>

### `@fastify/helmet`: hàng rào header mặc định

```ts title="src/app.ts"
import helmet from "@fastify/helmet";

await app.register(helmet);
```

Đăng ký với cấu hình mặc định là đủ cho một JSON API (không cần tinh chỉnh Content-Security-Policy phức tạp như một trang HTML render phía server). Helmet tự thêm các response header giảm thiểu một số lớp tấn công phía trình duyệt — ví dụ ngăn trình duyệt tự đoán loại nội dung khác với `Content-Type` khai báo. Đây là lớp phòng thủ **bổ sung**, không thay thế cho validate input hay authorization.

### CORS: allowlist origin, không phải `'*'`

```ts title="src/app.ts"
import cors from "@fastify/cors";
import { env } from "./env.js";

await app.register(cors, {
  origin: env.ALLOWED_ORIGINS.split(","),
  credentials: true,
});
```

`env.ALLOWED_ORIGINS` là một biến môi trường mới, ví dụ `http://localhost:5173,https://app.taskflow.example`. `@fastify/cors` tự so khớp `Origin` header của request với danh sách này — nếu khớp, trả đúng origin đó trong `Access-Control-Allow-Origin` (không phải `'*'`); nếu không khớp, không thêm header cho phép.

**Vì sao không dùng `'*'`?** Vì `/auth/refresh` (B05) gửi refresh token qua cookie `httpOnly`. Theo đặc tả CORS, `Access-Control-Allow-Origin: '*'` KHÔNG được phép đi kèm `Access-Control-Allow-Credentials: true` — trình duyệt sẽ chặn response nếu server cố trả cả hai. Muốn hỗ trợ cookie, server bắt buộc phải khai một origin cụ thể, lấy từ allowlist đã kiểm tra — không có cách nào lách qua yêu cầu này.

### So sánh các cách cấu hình `origin`

| Lựa chọn | Ưu | Nhược | Dùng khi |
|---|---|---|---|
| `origin: '*'` | Đơn giản, không cần bảo trì allowlist | Không thể dùng cùng `credentials: true` — vi phạm CORS spec | API công khai, không cookie/session (ví dụ API đọc dữ liệu công khai) |
| `origin: [danh sách tĩnh]` | An toàn, rõ ràng, dễ audit | Phải cập nhật khi thêm domain frontend mới | `taskflow-api` — số lượng frontend origin cố định, ít thay đổi |
| `origin: (origin, cb) => ...` (hàm động) | Linh hoạt cho multi-tenant với domain riêng từng khách hàng | Phức tạp hơn, viết sai logic có thể vô tình cho phép mọi origin | Sản phẩm SaaS multi-tenant cho phép khách gắn domain riêng (chưa phải nhu cầu hiện tại của `taskflow-api`) |

</Technical>

<Callout type="warning">
  `origin: '*'` cộng với `credentials: true` KHÔNG hoạt động — đây không phải một tuỳ chọn cấu hình sai nhẹ, mà là một kết hợp trình duyệt sẽ chủ động chặn theo đặc tả CORS. Nếu `taskflow-api` cần hỗ trợ cookie (đúng như thiết kế từ B05), origin bắt buộc phải là danh sách cụ thể — không có đường tắt.
</Callout>

<Callout type="mistake">
  Đăng ký `@fastify/cors` với `origin: true` (cho phép mọi origin phản chiếu lại) để "cho dễ debug" rồi quên đổi lại trước khi deploy. Về mặt hành vi với trình duyệt, điều này gần như tương đương `'*'` nhưng dễ bị bỏ sót hơn khi review code vì trông có vẻ là một cấu hình hợp lệ.
</Callout>
