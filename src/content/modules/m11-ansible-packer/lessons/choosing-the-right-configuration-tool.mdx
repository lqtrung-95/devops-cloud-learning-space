<Eli5 title="Ba cách giao việc cho một nhân viên mới" emoji="🧭">

Cách 1: nhân viên đã làm việc lâu năm (server đang chạy), bạn **gọi điện dặn thêm việc** bất cứ lúc nào — đó là Ansible qua SSH.

Cách 2: nhân viên **mới vào ngày đầu tiên** được đưa một tờ hướng dẫn ngắn để tự đọc rồi bắt tay vào việc, không ai theo sát sau đó — đó là EC2 user data, chỉ chạy một lần lúc "sinh ra".

Cách 3: bạn **không tuyển và đào tạo nữa** — bạn thuê hẳn một đội đã được training bài bản y hệt nhau từ trước (golden image/container), đội nào cũng làm việc giống hệt đội kia. Muốn đổi quy trình, bạn đào tạo lại **cả đội mới** thay vì huấn luyện lại đội cũ.

Không có cách nào "luôn đúng" — công ty thật dùng cả ba tuỳ vị trí công việc.

</Eli5>

<Technical>

### Ba lựa chọn và khi nào dùng

**1. Ansible qua SSH (mutable, đã học ở bài 2–3)**

- Phù hợp: server sống lâu, ít instance (bastion host, CI self-hosted runner, một vài server nền tảng), cần đổi cấu hình thường xuyên mà không muốn rebuild image mỗi lần.
- Rủi ro: nếu không kỷ luật (luôn chạy qua playbook, không SSH tay sửa trực tiếp), dễ quay lại configuration drift đã học ở bài 1.

**2. EC2 user data (chạy 1 lần lúc boot)**

```bash title="user_data.sh"
#!/bin/bash
set -euo pipefail
echo "ECS_CLUSTER=shop-prod" >> /etc/ecs/ecs.config
/usr/bin/aws ssm get-parameter --name /shop/api-token --with-decryption \
  --query Parameter.Value --output text > /etc/app/token
systemctl restart app-agent
```

- Chạy **một lần duy nhất** khi instance khởi động, log ở `/var/log/cloud-init-output.log`.
- Phù hợp: vài dòng bootstrap đơn giản — set hostname, join ECS cluster, tải 1 file config từ SSM.
- Không phù hợp: logic phức tạp, cần idempotency chặt chẽ, hoặc phải áp dụng lại cho instance **đang chạy** (user data không tự chạy lại khi bạn sửa nó, trừ khi thay instance).

**3. Golden image / container (immutable, bài 4)**

- Phù hợp: fleet lớn cần nhất quán tuyệt đối, muốn rollback tức thì, production app chạy dài hạn trên ASG.
- Đánh đổi: vòng lặp thay đổi chậm hơn (phải build + rollout) so với SSH sửa tại chỗ.

### Ma trận quyết định nhanh

| Tình huống | Chọn |
|---|---|
| Vá bảo mật khẩn cấp trên fleet 50 server đang chạy, không kịp build lại image | Ansible ad-hoc (`ansible web -m apt -a "name=openssl state=latest"`) — rồi vẫn nên đưa fix vào golden image cho lần build tới |
| App production chạy trên ASG, cần scale nhanh và consistency | Golden image (Packer) hoặc container image |
| Set 3 biến môi trường + tải 1 binary lúc EC2 khởi động | User data |
| Cấu hình bastion host dùng nhiều năm, ít khi đổi | Ansible, chạy định kỳ hoặc mỗi khi có thay đổi |
| Microservice chạy trên container orchestrator (K8s — học ở M12) | Container image, không dùng Ansible/user data cho app logic |

### Kết hợp cả ba trong một hệ thống thật

```text
1. Packer + Ansible role "hardening" + "node_exporter"  → golden AMI dùng chung cho MỌI server
2. Terraform launch template dùng golden AMI              → mỗi ASG (web, worker) kế thừa nền tảng đã hardening
3. User data ngắn trên launch template                    → chỉ set biến riêng cho từng ASG (APP_ROLE=web)
4. Ansible ad-hoc                                          → dùng khi cần vá khẩn cấp giữa hai lần build AMI
```

Nền tảng (OS, security baseline, monitoring agent) đi qua golden image; cấu hình đặc thù từng lần scale đi qua user data ngắn; và Ansible vẫn giữ vai trò công cụ vận hành/khẩn cấp.

### Container: khi nào KHÔNG cần Ansible/Packer nữa

Nếu app của bạn đã đóng gói bằng `Dockerfile` (M04) và chạy trên ECS/Kubernetes, bạn thường **không cần Ansible cho chính app đó** — image Docker đã đóng vai trò golden image ở tầng ứng dụng. Ansible/Packer khi đó lùi về vai trò chuẩn bị **node nền tảng** (worker node của cluster, bastion, CI runner) — nội dung sẽ gặp lại ở M12–M13 khi build node group cho EKS.

<Callout type="mistake">

**Dùng Ansible ad-hoc để vá lỗi khẩn cấp rồi quên đưa fix vào golden image.** Lần build AMI tiếp theo sẽ "quên" bản vá đó, và instance mới tạo ra sẽ lại thiếu fix. Luôn cập nhật role Ansible tương ứng ngay sau khi vá khẩn cấp.

</Callout>
