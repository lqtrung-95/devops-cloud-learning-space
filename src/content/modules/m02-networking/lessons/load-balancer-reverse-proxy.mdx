<Eli5 title="Load balancer giống như lễ tân dẫn khách vào bàn trong nhà hàng đông khách" emoji="💁">
  Nhà hàng có nhiều đầu bếp. Nếu khách tự đi thẳng vào bếp, người thì dồn một bếp, người thì lạc. Vì vậy có **lễ tân đứng cửa** (reverse proxy / load balancer): khách chỉ biết một cửa, lễ tân **chia khách lần lượt** cho từng bếp (round-robin) và **không dẫn vào bếp đang nghỉ ốm** (health check).

  Có hai kiểu lễ tân. **Lễ tân L4** chỉ nhìn **số bàn đặt** (IP:port), không mở thực đơn — cực nhanh nhưng không biết khách muốn gì. **Lễ tân L7** **đọc order** (HTTP path, header): món nướng đưa qua bếp nướng (`/api`), đồ uống đưa qua quầy bar (`/static`).

  Còn **forward proxy** thì ngược lại: là **người đi chợ hộ** cho nhân viên công ty — đứng phía *người dùng* để đi ra ngoài, không phải đứng phía nhà hàng.
</Eli5>

Gần như mọi hệ thống production đều có ít nhất một lớp proxy trước app: Nginx trên VM, AWS ALB/NLB, Ingress Controller trong Kubernetes, CDN. Hiểu L4 vs L7 giúp bạn chọn đúng loại, và biết vì sao app thấy IP client là IP của load balancer.

<Technical>

### Forward proxy vs reverse proxy

| | Forward proxy | Reverse proxy |
|---|---|---|
| Đứng phía | Client | Server |
| Ai biết proxy tồn tại | Client cấu hình (`HTTPS_PROXY`) | Client **không biết**, tưởng đang nói chuyện với server |
| Dùng để | Kiểm soát/ghi log truy cập ra Internet, cache | Load balancing, TLS termination, cache, nén, WAF, ẩn backend |
| Ví dụ | Squid, proxy công ty | Nginx, HAProxy, Envoy, Traefik, AWS ALB |

### L4 vs L7 load balancing

| | L4 (transport) | L7 (application) |
|---|---|---|
| Nhìn thấy | IP, port, TCP/UDP | Toàn bộ HTTP: host, path, header, cookie |
| Routing theo | 5-tuple | `Host`, path `/api/*`, header, method |
| TLS | Thường chuyển thẳng (passthrough) hoặc terminate | Terminate TLS để đọc HTTP |
| Hiệu năng | Rất cao, độ trễ thấp | Tốn CPU hơn nhưng linh hoạt |
| Giao thức | Mọi thứ trên TCP/UDP (DB, gRPC, game…) | HTTP/HTTPS, gRPC, WebSocket |
| AWS | Network Load Balancer (NLB) | Application Load Balancer (ALB) |

### Thuật toán & health check

- **Round-robin** (mặc định Nginx): lần lượt. **least_conn**: gửi tới máy ít kết nối nhất (hợp request dài). **ip_hash**/hash: cùng client → cùng backend (sticky, nhưng co giãn kém).
- **Passive health check** (Nginx mã nguồn mở): request lỗi `max_fails` lần trong `fail_timeout` → tạm loại máy. **Active health check** (gọi `/healthz` định kỳ) có ở HAProxy, Envoy, AWS ELB, Nginx Plus.

### IP client thật ở đâu?

Sau proxy, app thấy kết nối tới từ IP của proxy. Proxy cần gửi thêm header `X-Forwarded-For` (IP gốc), `X-Forwarded-Proto` (http/https); app/framework phải được cấu hình **chỉ tin header này từ proxy của mình** (vd Express `app.set("trust proxy", ...)`).

### Nginx: reverse proxy + round-robin cho 2 backend

```nginx title="/etc/nginx/sites-available/app.conf"
upstream api_backend {
    # round-robin mặc định; thêm "least_conn;" nếu muốn đổi thuật toán
    server 127.0.0.1:3001 max_fails=3 fail_timeout=10s;
    server 127.0.0.1:3002 max_fails=3 fail_timeout=10s;
}

server {
    listen 80;
    server_name app.example.com;

    location /api/ {
        proxy_pass http://api_backend;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_connect_timeout 3s;
        proxy_read_timeout    30s;
    }

    location / {
        root /var/www/app;
        try_files $uri /index.html;
    }
}
```

<Callout type="mistake" title="Quên dấu / trong proxy_pass">
  `proxy_pass http://api_backend;` giữ nguyên URI (`/api/users` → backend nhận `/api/users`). Còn `proxy_pass http://api_backend/;` (có `/` cuối) **thay** phần khớp `location` (`/api/users` → backend nhận `/users`). Một ký tự khác nhau → 404 hàng loạt.
</Callout>

<Callout type="warning" title="Ghi log sai IP client">
  Rate limit hoặc chặn IP theo `$remote_addr` ở backend sẽ chặn nhầm **chính load balancer** — tức là chặn tất cả mọi người. Hãy dùng IP từ `X-Forwarded-For` do proxy tin cậy của bạn gắn vào.
</Callout>

<Callout type="cost">
  Trên AWS, ALB/NLB tính tiền theo giờ **cộng** theo đơn vị năng lực sử dụng (LCU/NLCU). Mỗi môi trường thử nghiệm tạo một ALB riêng rồi quên xoá là khoản phí âm thầm hàng tháng.
</Callout>
