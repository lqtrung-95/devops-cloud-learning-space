<Eli5 title="VM giống nhà phố riêng, container giống căn hộ chung cư" emoji="🏢">
  **Máy ảo (VM)** giống một **căn nhà phố riêng**: có móng riêng, đường điện nước riêng, tường riêng. Rất riêng tư, nhưng xây mất nhiều thời gian và tốn đất.

  **Container** giống một **căn hộ trong chung cư**: mọi căn hộ **dùng chung móng và hệ thống điện nước** của toà nhà (chính là **kernel** của máy chủ). Mỗi căn vẫn có cửa khoá riêng, đồng hồ điện nước riêng — nên dọn vào ở gần như ngay lập tức.

  Còn cái tên "container" lấy từ **thùng hàng tiêu chuẩn trên tàu biển**: tàu nào, cảng nào, xe tải nào cũng chở được vì kích thước chuẩn. Image Docker cũng vậy — đóng gói một lần, chạy trên laptop, server hay cloud đều giống nhau.

  Chỗ ví von bị "gãy": tường giữa các căn hộ container **mỏng hơn** nhà phố. Nếu có lỗ hổng ở kernel (móng chung), một căn hộ có thể ảnh hưởng tới căn khác.
</Eli5>

### Vì sao DevOps cần container?

Trước container, câu kinh điển là "chạy trên máy em được mà!". Container gói app **cùng đúng phiên bản runtime và thư viện** thành một image bất biến. CI build image một lần, rồi chính image đó chạy ở staging và production — Kubernetes, ECS, Cloud Run đều nói chung một "ngôn ngữ" là container image.

### Container thực chất là một tiến trình Linux bị "nhốt"

Container **không phải máy ảo nhẹ**. Nó là tiến trình bình thường trên host, được kernel cô lập bằng hai cơ chế:

| Cơ chế | Làm gì | Ví von chung cư |
|---|---|---|
| **namespaces** | Che tầm nhìn: container chỉ thấy tiến trình, mạng, file, hostname của riêng nó | Tường và cửa của căn hộ |
| **cgroups** | Giới hạn và đo tài nguyên: CPU, RAM, I/O | Đồng hồ điện nước + cầu dao riêng |

Các namespace chính: `pid` (thấy PID riêng, app là PID 1), `net` (card mạng, IP riêng), `mnt` (cây thư mục riêng), `uts` (hostname), `ipc`, `user` (map UID).

### VM vs container

| | Virtual Machine | Container |
|---|---|---|
| Cô lập | Phần cứng ảo + kernel riêng | Namespaces + cgroups, **chung kernel** |
| Khởi động | Vài chục giây – phút | Thường dưới 1 giây |
| Kích thước | GB | MB – vài trăm MB |
| Chạy OS khác kernel? | Được (Windows trên host Linux) | Không: container Linux cần kernel Linux |
| Dùng khi | Cần cô lập mạnh, multi-tenant, OS khác | Đóng gói app, microservices, CI |

Thực tế trên cloud thường **kết hợp cả hai**: container chạy bên trong VM (EC2, node của EKS).

<Callout type="info" title="Docker Desktop trên macOS/Windows">

Kernel macOS không phải Linux, nên Docker Desktop âm thầm chạy **một VM Linux nhỏ** và các container nằm trong VM đó. Đây là lý do bind mount trên Mac chậm hơn trên Linux.

</Callout>

### OCI và các thành phần của Docker

- **OCI** (Open Container Initiative) chuẩn hoá **image format** và **runtime**. Image build bằng Docker chạy được trên containerd, Podman, Kubernetes…
- Khi bạn gõ `docker run`: **docker CLI** → gọi API của **dockerd** → **containerd** quản lý vòng đời → **runc** gọi kernel tạo namespaces/cgroups rồi chạy tiến trình.
- Kubernetes hiện nay nói chuyện thẳng với containerd (hoặc CRI-O), không cần dockerd — nhưng image bạn build bằng Docker vẫn dùng bình thường.

</Technical>

<Callout type="mistake">

**Coi container như VM**: SSH vào container, cài thêm package bằng tay, sửa file cấu hình trực tiếp. Container là **dùng xong vứt (ephemeral)** — lần tạo lại tiếp theo mọi thay đổi tay đều biến mất. Mọi thay đổi phải nằm trong Dockerfile hoặc cấu hình truyền vào lúc chạy.

</Callout>

<Callout type="warning">

Mặc định tiến trình trong container thường chạy bằng **root** (UID 0) — và vì chung kernel, root trong container vẫn là chuyện nghiêm túc nếu có lỗ hổng thoát container. Bài "Dockerfile chuẩn production" sẽ chuyển sang user thường.

</Callout>
