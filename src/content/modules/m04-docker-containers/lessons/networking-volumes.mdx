<Eli5 title="Network và volume giống hệ thống liên lạc và kho gửi đồ của chung cư" emoji="🏘️">

Các căn hộ trong cùng một **toà chung cư** (network) gọi nhau qua **điện thoại nội bộ bằng số phòng**: "alo phòng `db`". Không ai cần nhớ số điện thoại thật — lễ tân (**DNS nội bộ của Docker**) tự nối máy, kể cả khi căn hộ đổi người ở.

Người **ngoài phố** thì không gọi nội bộ được. Muốn vào phải qua **cổng chính có bảo vệ** — đó là **publish port** (`-p 8080:80`): khách tới cổng 8080, bảo vệ dẫn lên phòng web cửa số 80.

Về đồ đạc: đồ để trong căn hộ thuê (**writable layer**) sẽ **mất khi trả phòng**. Muốn giữ lâu dài thì gửi vào **kho của ban quản lý** (**named volume**), hoặc mang **đồ từ nhà mình** tới dùng tạm (**bind mount** — thư mục trên máy host).

</Eli5>

### Vì sao DevOps quan tâm?

Hai sự cố kinh điển của người mới: "API không kết nối được database dù cả hai đang chạy" (sai network/hostname) và "restart xong mất sạch dữ liệu" (không dùng volume). Hiểu rõ phần này cũng là nền tảng cho Service, PersistentVolume trong Kubernetes.

<Technical>

### Các loại network driver

| Driver | Đặc điểm | Dùng khi |
|---|---|---|
| **bridge** (mặc định) | Mạng ảo riêng trên host, container có IP nội bộ, ra Internet qua NAT | Hầu hết trường hợp một host |
| **user-defined bridge** | Như bridge nhưng **có DNS theo tên container/service**, cô lập theo nhóm | Luôn tạo network riêng cho từng app (Compose làm sẵn) |
| **host** | Container dùng thẳng network stack của host, không cần `-p` | Cần hiệu năng mạng tối đa; hỗ trợ đầy đủ trên Linux |
| **none** | Không có mạng | Job xử lý dữ liệu cần cô lập tuyệt đối |

Điểm dễ nhầm: network **bridge mặc định** (tên `bridge`) **không** có DNS theo tên. Chạy `docker run` không chỉ định `--network` thì container phải gọi nhau bằng IP — thứ thay đổi mỗi lần tạo lại. Hãy luôn dùng user-defined network.

### `localhost` trong container là chính container đó

Mỗi container có network namespace riêng. API gọi `localhost:5432` là gọi port 5432 **bên trong container API** — không phải database. Gọi đúng: `db:5432`.

### Publish port

```bash
docker run -p 8080:80 nginx            # 0.0.0.0:8080 trên host → port 80 container
docker run -p 127.0.0.1:5432:5432 postgres  # chỉ máy host truy cập được
```

`EXPOSE` trong Dockerfile chỉ là **tài liệu** — không mở port nào cả. Chỉ `-p` / `ports:` mới publish.

### Ba cách lưu dữ liệu

| | Named volume | Bind mount | tmpfs |
|---|---|---|---|
| Nằm ở đâu | Docker quản lý (`/var/lib/docker/volumes/…` trên Linux) | Đường dẫn bạn chỉ định trên host | RAM |
| Sống sót khi xoá container | ✅ | ✅ (là file của host) | ❌ |
| Dùng cho | Dữ liệu database, upload | Code khi dev (hot-reload), file cấu hình | Dữ liệu tạm, nhạy cảm |
| Phụ thuộc cấu trúc host | Không | Có — kém portable | Không |

```bash
# Cú pháp --mount rõ ràng hơn -v, nên dùng trong script
docker volume create pgdata
docker run -d --name db \
  --network app-net \
  --mount type=volume,src=pgdata,dst=/var/lib/postgresql/data \
  -e POSTGRES_PASSWORD=devpass postgres:17-alpine

docker run -d --name web -p 8080:80 \
  --mount type=bind,src="$(pwd)/nginx.conf",dst=/etc/nginx/conf.d/default.conf,readonly \
  nginx:1.27-alpine
```

Đường dẫn dữ liệu bên trong image có thể đổi giữa các major version (ví dụ Postgres 18 đổi cách tổ chức thư mục data) — luôn đọc trang Docker Hub của image trước khi mount.

### Backup một volume

Volume chỉ là thư mục — chạy một container tạm mount volume đó và nén lại:

```bash
docker run --rm -v pgdata:/data:ro -v "$(pwd)":/backup alpine \
  tar czf /backup/pgdata-$(date +%F).tar.gz -C /data .
```

Với database, cách đúng hơn là dump logic (`pg_dump`) để tránh copy file khi DB đang ghi.

</Technical>

<Callout type="mistake">

**API dùng `localhost:5432` để gọi database trong container khác.** Bên trong container, `localhost` là chính nó. Dùng tên service/container (`db:5432`) trên cùng user-defined network.

</Callout>

<Callout type="warning" title="Docker publish port có thể vượt mặt firewall">

Trên Linux, Docker tự thêm rule iptables cho port được publish. Với `ufw`, port publish kiểu `-p 5432:5432` thường **vẫn truy cập được từ Internet** dù ufw không cho phép. Database đừng publish ra host; nếu cần cho công cụ trên máy host, bind `127.0.0.1:5432:5432`. Trên cloud, thêm một lớp Security Group chặn từ bên ngoài.

</Callout>

<Callout type="tip">

Bind mount trên Docker Desktop (macOS/Windows) chậm hơn trên Linux vì file phải đi qua VM. Thư mục nặng như `node_modules` nên để trong named volume thay vì bind mount.

</Callout>
