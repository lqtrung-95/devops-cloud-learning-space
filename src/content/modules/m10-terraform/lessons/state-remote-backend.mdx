<Eli5 title="State giống như sổ kiểm kê kho có một chìa khoá duy nhất" emoji="📒">

Kho hàng của công ty có một **sổ kiểm kê**: kệ A có 10 thùng, kệ B có 5 thùng. Terraform cũng có sổ như vậy — file **state** — ghi "block `aws_vpc.main` trong code chính là `vpc-0f1e...` trên AWS".

Nếu mỗi thủ kho giữ **một bản sổ riêng trong cặp** (state local trên laptop), chẳng ai biết người kia đã nhập xuất gì. Nên sổ phải để ở **văn phòng chung** (remote backend, ví dụ S3).

Nhưng văn phòng chung lại có rủi ro mới: hai người cùng mở sổ và cùng ghi một lúc thì người ghi sau xoá mất dòng của người trước. Giải pháp: sổ có **một chìa khoá** (lock) — ai đang ghi thì giữ chìa, người kia phải chờ.

</Eli5>

Mất hoặc hỏng state là một trong những sự cố Terraform đau đớn nhất: tài nguyên vẫn chạy (và vẫn tính tiền) nhưng Terraform "quên" chúng. Vì vậy thiết lập remote state **có locking, versioning, mã hoá** là việc đầu tiên khi làm Terraform theo nhóm.

<Technical>

### State chứa gì

`terraform.tfstate` là JSON gồm: `serial` (tăng mỗi lần ghi), `lineage` (định danh của chuỗi state), và danh sách tài nguyên với **ID thật + toàn bộ thuộc tính**. Hệ quả:

- State có thể chứa **secret dạng rõ** (mật khẩu DB, private key) → bucket state phải được bảo vệ như secret.
- Không bao giờ sửa tay file state. Dùng các lệnh `terraform state`.

### Local vs remote backend

| | Local (`terraform.tfstate` cạnh code) | Remote (S3, HCP Terraform…) |
|---|---|---|
| Chia sẻ cho team/CI | Không | Có |
| Locking | Chỉ trong một máy | Có (tuỳ backend) |
| Mất laptop | Mất state | An toàn, có versioning |
| Dùng cho | Thử nghiệm cá nhân | Mọi thứ thật |

### S3 backend với native locking

Trước đây S3 backend cần thêm **một bảng DynamoDB** để làm khoá. Các bản Terraform gần đây (native S3 locking xuất hiện khoảng 1.10 và ổn định từ 1.11 — kiểm tra tài liệu mới nhất) hỗ trợ `use_lockfile = true`: Terraform tạo file `<key>.tflock` ngay trong bucket bằng **conditional write** của S3. Tham số `dynamodb_table` được đánh dấu deprecated. OpenTofu cũng có tính năng tương tự.

```hcl title="bootstrap/main.tf"
resource "aws_s3_bucket" "tfstate" {
  bucket = "shop-tfstate-123456789012"

  lifecycle {
    prevent_destroy = true
  }
}

resource "aws_s3_bucket_versioning" "tfstate" {
  bucket = aws_s3_bucket.tfstate.id
  versioning_configuration {
    status = "Enabled"
  }
}

resource "aws_s3_bucket_server_side_encryption_configuration" "tfstate" {
  bucket = aws_s3_bucket.tfstate.id
  rule {
    apply_server_side_encryption_by_default {
      sse_algorithm = "aws:kms"
    }
  }
}

resource "aws_s3_bucket_public_access_block" "tfstate" {
  bucket                  = aws_s3_bucket.tfstate.id
  block_public_acls       = true
  block_public_policy     = true
  ignore_public_acls      = true
  restrict_public_buckets = true
}
```

```hcl title="envs/dev/backend.tf"
terraform {
  backend "s3" {
    bucket       = "shop-tfstate-123456789012"
    key          = "dev/terraform.tfstate"
    region       = "ap-southeast-1"
    encrypt      = true
    use_lockfile = true
  }
}
```

Bucket state là chuyện "con gà quả trứng": tạo nó bằng một thư mục `bootstrap/` dùng state local (hoặc tạo tay một lần), sau đó mọi stack khác dùng backend S3. Block `backend` **không nhận biến** — muốn đổi giá trị theo môi trường thì dùng `terraform init -backend-config=dev.s3.tfbackend`.

IAM cho người/CI chạy Terraform cần `s3:ListBucket` trên bucket, `s3:GetObject`/`s3:PutObject` trên key state, và `s3:GetObject`/`s3:PutObject`/`s3:DeleteObject` trên file `.tflock`.

### Các lệnh state

| Lệnh | Dùng khi |
|---|---|
| `terraform state list` | Xem Terraform đang quản lý những gì |
| `terraform state show aws_vpc.main` | Xem thuộc tính một tài nguyên |
| `terraform state mv A B` | Đổi tên/di chuyển địa chỉ mà không tạo lại (nay nên dùng block `moved`) |
| `terraform state rm A` | Terraform "quên" tài nguyên, **không xoá** trên AWS (nay có block `removed`) |
| `terraform import A id` | Đưa tài nguyên có sẵn vào state (nay nên dùng block `import`) |
| `terraform force-unlock LOCK_ID` | Gỡ khoá bị kẹt khi tiến trình chết giữa chừng |

</Technical>

<Callout type="mistake">

**Commit `terraform.tfstate` vào Git.** Vừa lộ secret, vừa không có locking, vừa dễ conflict. Thêm `*.tfstate`, `*.tfstate.*` và `.terraform/` vào `.gitignore` ngay từ đầu.

</Callout>

<Callout type="warning" title="force-unlock chỉ khi chắc chắn">

Chỉ chạy `terraform force-unlock` khi đã xác nhận không còn tiến trình nào đang apply (ví dụ job CI đã bị huỷ). Gỡ khoá của một apply đang chạy chính là tạo ra kịch bản ghi đè trong hình ở trên.

</Callout>

<Callout type="tip" title="Chia nhỏ state">

Một state khổng lồ cho cả công ty làm plan chậm và "bán kính nổ" lớn. Tách theo môi trường và theo lớp (`network`, `data`, `app`) — ví dụ key `dev/network/terraform.tfstate`.

</Callout>
