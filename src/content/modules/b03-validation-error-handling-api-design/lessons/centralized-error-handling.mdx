Lesson trước, Zod đã chặn được input xấu — nhưng response lỗi vẫn là format mặc định của Fastify (`FST_ERR_VALIDATION`, `statusCode`), không phải format chuẩn `{ error: { code, message, details } }` mà `docs/backend-curriculum.md` đã chốt cho toàn bộ 19 module. Module này lắp `setErrorHandler` — nơi DUY NHẤT quyết định response lỗi trông như thế nào, dù lỗi đến từ Zod, từ logic nghiệp vụ, hay từ một bug không ai lường trước.

### Định nghĩa lỗi nghiệp vụ bằng class riêng

```typescript title="src/errors/app-error.ts"
export class AppError extends Error {
  constructor(
    public readonly statusCode: number,
    public readonly code: string,
    message: string,
    public readonly details?: unknown[],
  ) {
    super(message);
    this.name = "AppError";
  }
}

export class NotFoundError extends AppError {
  constructor(message = "Resource not found") {
    super(404, "NOT_FOUND", message);
  }
}

export class ConflictError extends AppError {
  constructor(message = "Resource conflict") {
    super(409, "CONFLICT", message);
  }
}
```

Handler giờ chỉ cần `throw new NotFoundError()` — không tự viết `reply.code(404).send(...)` ở từng nơi.

```typescript title="src/routes/projects.route.ts"
fastify.get("/api/v1/projects/:id", { schema: { params: projectParamsSchema } }, async (request) => {
  const project = findProjectById(request.params.id);
  if (!project) throw new NotFoundError(`Project ${request.params.id} not found`);
  return project;
});
```

### `setErrorHandler` — bộ não phân loại

```typescript title="src/app.ts"
import { ZodError } from "zod";
import { hasZodFastifySchemaValidationErrors } from "fastify-type-provider-zod";
import { AppError } from "./errors/app-error";

fastify.setErrorHandler((error, request, reply) => {
  // 1. Lỗi validation từ Zod schema gắn ở route
  if (hasZodFastifySchemaValidationErrors(error)) {
    return reply.code(422).send({
      error: {
        code: "VALIDATION_ERROR",
        message: "Request không hợp lệ",
        details: error.validation.map((item) => ({
          path: item.instancePath || item.params?.["missingProperty"],
          message: item.message,
        })),
      },
    });
  }

  // 2. Lỗi nghiệp vụ tự định nghĩa — đã biết chính xác statusCode + code
  if (error instanceof AppError) {
    return reply.code(error.statusCode).send({
      error: { code: error.code, message: error.message, details: error.details ?? [] },
    });
  }

  // 3. Lỗi Zod ném trực tiếp (vd .parse() gọi tay ngoài route schema)
  if (error instanceof ZodError) {
    return reply.code(422).send({
      error: {
        code: "VALIDATION_ERROR",
        message: "Request không hợp lệ",
        details: error.issues.map((issue) => ({ path: issue.path.join("."), message: issue.message })),
      },
    });
  }

  // 4. Mọi thứ còn lại — log đầy đủ, KHÔNG lộ chi tiết ra ngoài
  request.log.error({ err: error }, "Unhandled error");
  return reply.code(500).send({
    error: { code: "INTERNAL_ERROR", message: "Đã có lỗi xảy ra, vui lòng thử lại sau", details: [] },
  });
});
```

Thứ tự kiểm tra quan trọng: `AppError` cụ thể phải được bắt trước nhánh "mọi thứ còn lại", nếu không mọi lỗi nghiệp vụ sẽ rơi vào nhánh `500` chung chung.

### Vì sao không trả `error.message` gốc ở nhánh 500

| Cách làm | Ưu | Nhược | Dùng khi |
|---|---|---|---|
| Trả nguyên `error.message`/`stack` | Debug nhanh lúc dev | Rò tên bảng, câu SQL, đường dẫn nội bộ cho client | Không bao giờ ở production |
| Trả message chung + log server-side | An toàn, vẫn debug được qua log + `requestId` | Cần hạ tầng log tốt (nối tới B16 Observability) | Luôn dùng cách này |

`request.log.error` (pino, có sẵn từ B01) ghi đầy đủ error xuống log server — nơi chỉ người có quyền truy cập mới đọc được, khác hẳn response trả thẳng ra Internet.

<Callout type="mistake">
  Quên đặt nhánh `AppError` TRƯỚC nhánh "còn lại" (`else`) — kết quả là `NotFoundError` (nên trả `404`) lại rơi vào nhánh `500` chung chung. Luôn kiểm tra `instanceof` từ cụ thể tới chung chung.
</Callout>

<Callout type="warning">
  Đừng bao giờ nội suy trực tiếp input người dùng vào `message` mà không escape khi message đó có thể chứa dữ liệu nhạy cảm (vd token, password field value) — dù chỉ để debug. Log cũng là nơi có thể bị đọc trộm.
</Callout>
