Còn hai việc cuối để hoàn thiện API design của `taskflow-api`: đảm bảo request `POST` quan trọng không bị lặp khi client retry (idempotency), và cho client bên ngoài một tấm bản đồ đáng tin cậy để tự khám phá API mà không cần đọc code.

<Technical title="Idempotency cho POST quan trọng">

### Vấn đề: client retry khi mất mạng

Client gọi `POST /api/v1/tasks`, mạng chập chờn, client không nhận được response nên **tự động gửi lại** cùng request. Nếu request đầu tiên thực ra đã thành công (chỉ là response bị mất trên đường về), server sẽ tạo **hai** task giống hệt nhau.

### Idempotency key — kiểm tra TRƯỚC khi thực thi

Giải pháp: client gửi kèm header `Idempotency-Key` (một UUID tự sinh ở phía client cho MỖI thao tác logic, không phải mỗi HTTP request). Server lưu lại key này cùng kết quả của lần xử lý đầu tiên. Điểm bắt buộc: **server phải tra key này TRƯỚC khi chạy side effect** (tạo task), không phải sau.

```typescript title="src/plugins/idempotency.ts"
import type { FastifyRequest, FastifyReply } from "fastify";

// Map tạm thời — thực tế nên dùng Redis (có TTL) khi taskflow-api có Redis từ B09
const idempotencyStore = new Map<string, { statusCode: number; body: unknown }>();

export async function checkIdempotencyKey(request: FastifyRequest, reply: FastifyReply) {
  const key = request.headers["idempotency-key"];
  if (!key || typeof key !== "string") return; // header optional — route tự quyết định có bắt buộc hay không

  const cached = idempotencyStore.get(key);
  if (cached) {
    // Đã xử lý key này trước đó — trả lại CHÍNH XÁC kết quả cũ, không chạy lại side effect
    reply.code(cached.statusCode).send(cached.body);
    return reply; // báo Fastify dừng lifecycle tại đây, không vào handler
  }
}

export function saveIdempotencyResult(key: string | undefined, statusCode: number, body: unknown) {
  if (key) idempotencyStore.set(key, { statusCode, body });
}
```

```typescript title="src/routes/tasks.route.ts"
fastify.post(
  "/api/v1/tasks",
  { schema: { body: createTaskBodySchema }, preHandler: checkIdempotencyKey },
  async (request, reply) => {
    const task = createTask(request.body); // side effect thật sự
    saveIdempotencyResult(request.headers["idempotency-key"] as string | undefined, 201, task);
    return reply.code(201).send(task);
  },
);
```

`preHandler` chạy TRƯỚC handler chính — đây chính là "kiểm tra trước khi thực thi side effect". Nếu đặt logic kiểm tra key BÊN TRONG handler, sau dòng `createTask(...)`, thì side effect đã lỡ chạy — mất hết ý nghĩa chống trùng, dù code trông có vẻ tương tự.

<Callout type="warning">
  Idempotency key chỉ có tác dụng nếu được tra và lưu ở đúng nơi (trước side effect, trong cùng transaction về mặt logic). Kiểm tra key SAU khi đã `createTask` chỉ giúp client thứ hai nhận response nhanh hơn — task trùng đã được tạo trước đó rồi.
</Callout>

</Technical>

<Technical title="Tự sinh OpenAPI từ schema Zod đang dùng để validate">

### Cài đặt và đăng ký plugin

```typescript title="src/app.ts"
import fastifySwagger from "@fastify/swagger";
import fastifySwaggerUi from "@fastify/swagger-ui";
import { jsonSchemaTransform } from "fastify-type-provider-zod";

await fastify.register(fastifySwagger, {
  openapi: {
    info: { title: "taskflow-api", version: "1.0.0" },
    servers: [{ url: "http://localhost:3000" }],
  },
  transform: jsonSchemaTransform, // chuyển Zod schema đã gắn ở route sang JSON Schema cho OpenAPI
});

await fastify.register(fastifySwaggerUi, {
  routePrefix: "/docs",
});
```

`jsonSchemaTransform` là mấu chốt: nó đọc ĐÚNG object schema Zod bạn đã truyền vào `{ schema: { body: createTaskBodySchema } }` ở mỗi route — không phải một định nghĩa OpenAPI viết tay riêng trong file `.yaml`.

### Một nguồn sự thật — không phải trùng hợp

| Cách làm | Ưu | Nhược | Dùng khi |
|---|---|---|---|
| Viết OpenAPI `.yaml`/`.json` tay, tách biệt code validate | Kiểm soát format tài liệu chi tiết hơn | Rất dễ lệch: sửa schema code quên sửa doc (hoặc ngược lại) | API cực kỳ ổn định, có team docs riêng |
| Sinh OpenAPI từ CHÍNH schema validate (Zod → `jsonSchemaTransform`) | Doc luôn khớp 100% với validate thật đang chạy | Format OpenAPI phụ thuộc cách Zod schema được viết | Mặc định cho hầu hết team — đúng cách `taskflow-api` chọn |

Đây là nguyên tắc chung "một nguồn sự thật" (single source of truth) — cùng nguyên lý với việc dùng `z.infer` để suy type thay vì viết interface trùng lặp ở lesson đầu module này.

### Thêm mô tả cho response (tuỳ chọn nhưng nên làm)

```typescript title="src/routes/tasks.route.ts"
fastify.post(
  "/api/v1/tasks",
  {
    schema: {
      body: createTaskBodySchema,
      response: { 201: taskResponseSchema },
      tags: ["tasks"],
      summary: "Tạo task mới trong project",
    },
  },
  async (request, reply) => {
    /* ... */
  },
);
```

`response` schema vừa validate output (bắt lỗi nếu handler trả thiếu field) vừa xuất hiện trong `/docs` như một ví dụ response mẫu.

Chỉ bắt buộc cho POST có side effect thật sự tốn kém khi trùng (tạo task, tạo thanh toán...).
</Callout>
