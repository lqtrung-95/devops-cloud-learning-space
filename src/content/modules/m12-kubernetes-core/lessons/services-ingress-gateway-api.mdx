<Eli5 title="Service giống như số tổng đài của một công ty" emoji="☎️">

Nhân viên chăm sóc khách hàng nghỉ việc, đổi ca, thêm người liên tục. Nếu khách phải nhớ **số di động của từng nhân viên** thì hỏng. Công ty in lên website **một số tổng đài 1900** — gọi vào là được nối tới một nhân viên đang rảnh. Đó là **Service**: một cái tên + IP cố định đứng trước những pod luôn thay đổi.

Tổng đài tìm nhân viên theo **bảng tên đeo ngực** (label `app: api`), không theo tên người. Ai đeo đúng bảng tên và **đang trong ca (Ready)** thì được nối máy.

Còn khách từ ngoài đường vào toà nhà thì đi qua **cổng + bảng chỉ dẫn ở sảnh**: "/api → tầng 2, / → tầng 1". Đó là **Ingress** hoặc thế hệ mới hơn, **Gateway API**.

</Eli5>

## Vì sao DevOps cần hiểu phần này?

Phần lớn sự cố "deploy xong mà không truy cập được" nằm ở tầng này: selector không khớp, sai `targetPort`, pod không Ready, route trỏ nhầm Service. Hiểu đường đi của một request giúp bạn debug từng chặng thay vì đoán mò.

<Technical>

### Service & các loại

```yaml title="api-service.yaml"
apiVersion: v1
kind: Service
metadata:
  name: api
  namespace: shop
spec:
  type: ClusterIP
  selector:
    app: api            # chọn pod có label này
  ports:
    - name: http
      port: 80          # cổng của Service
      targetPort: 8080  # cổng container đang lắng nghe
```

| Type | Truy cập từ | Ghi chú |
|---|---|---|
| `ClusterIP` (mặc định) | Chỉ trong cluster | Dùng cho giao tiếp nội bộ giữa các service |
| `NodePort` | `<NodeIP>:30000–32767` | Chủ yếu cho lab/debug |
| `LoadBalancer` | IP/DNS load balancer của cloud | Mỗi Service = 1 LB (tốn tiền trên AWS!) |
| Headless (`clusterIP: None`) | DNS trả thẳng IP pod | Dùng với StatefulSet |

- Service chọn pod qua **label selector**; danh sách IP pod Ready nằm trong **EndpointSlice** (`discovery.k8s.io/v1`). API `Endpoints` cũ đã bị deprecate.
- **kube-proxy** (hoặc CNI như Cilium) lập trình luật để IP ảo của Service phân tải tới các pod.

### DNS nội bộ

CoreDNS tạo bản ghi cho mọi Service: `<service>.<namespace>.svc.cluster.local`.

- Cùng namespace: gọi `http://api`.
- Khác namespace: gọi `http://api.shop` hoặc tên đầy đủ.

### Ingress — cách cũ, vẫn phổ biến

```yaml title="shop-ingress.yaml"
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: shop
spec:
  ingressClassName: example-class     # do controller bạn cài cung cấp
  rules:
    - host: shop.local
      http:
        paths:
          - path: /api
            pathType: Prefix
            backend:
              service:
                name: api
                port:
                  number: 80
          - path: /
            pathType: Prefix
            backend:
              service:
                name: frontend
                port:
                  number: 80
```

Ingress chỉ là **tờ yêu cầu** — cần một **Ingress controller** đọc và thực thi. Hạn chế: chỉ HTTP cơ bản, tính năng nâng cao (rewrite, canary, header) nằm rải rác trong annotation riêng của từng controller.

<Callout type="warning" title="ingress-nginx đã được thông báo ngừng phát triển">

Dự án cộng đồng **ingress-nginx** (Kubernetes SIG Network) đã thông báo nghỉ hưu vào khoảng đầu 2026, sau đó không còn bản vá bảo mật. Rất nhiều tutorial cũ vẫn dùng nó — với dự án mới hãy chọn **Gateway API** hoặc một controller còn được bảo trì. Kiểm tra tài liệu mới nhất trước khi chọn.

</Callout>

### Gateway API — thế hệ kế tiếp (`gateway.networking.k8s.io/v1`)

Tách vai trò giống toà nhà văn phòng:

| Resource | Ai quản lý | Ví von |
|---|---|---|
| `GatewayClass` | Nhà cung cấp hạ tầng | Loại cổng (hãng Envoy, Cilium, AWS…) |
| `Gateway` | Team platform | Cổng cụ thể: cổng 80/443, chứng chỉ TLS, namespace nào được gắn route |
| `HTTPRoute` | Team ứng dụng | Bảng chỉ dẫn của từng công ty thuê |

```yaml title="shop-gateway.yaml"
apiVersion: gateway.networking.k8s.io/v1
kind: Gateway
metadata:
  name: shop-gateway
  namespace: shop
spec:
  gatewayClassName: eg                # ví dụ: Envoy Gateway
  listeners:
    - name: http
      protocol: HTTP
      port: 80
      allowedRoutes:
        namespaces:
          from: Same
---
apiVersion: gateway.networking.k8s.io/v1
kind: HTTPRoute
metadata:
  name: shop-routes
  namespace: shop
spec:
  parentRefs:
    - name: shop-gateway
  hostnames:
    - shop.local
  rules:
    - matches:
        - path:
            type: PathPrefix
            value: /api
      backendRefs:
        - name: api
          port: 80
    - matches:
        - path:
            type: PathPrefix
            value: /
      backendRefs:
        - name: frontend
          port: 80
```

Điểm cộng: header/query matching, **traffic splitting theo weight** (canary), redirect/rewrite được chuẩn hoá trong spec — không phụ thuộc annotation. Gateway API và HTTPRoute nằm trong chương trình thi CKA hiện tại.

</Technical>

<Callout type="mistake">

**Nhầm `port` và `targetPort`.** `port` là số tổng đài khách gọi; `targetPort` là số máy lẻ của nhân viên (cổng container lắng nghe). App nghe 8080 mà `targetPort: 80` thì EndpointSlice vẫn có IP nhưng mọi request bị `connection refused`.

</Callout>

<Callout type="cost" title="Mỗi Service LoadBalancer = một load balancer tính tiền">

Trên AWS, 10 Service type `LoadBalancer` có thể thành 10 NLB tính phí theo giờ. Gom traffic HTTP qua một Gateway/Ingress dùng chung, còn service nội bộ để `ClusterIP`.

</Callout>
