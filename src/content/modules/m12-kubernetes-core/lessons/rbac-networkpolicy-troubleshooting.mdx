<Eli5 title="RBAC là thẻ ra vào, NetworkPolicy là tường ngăn giữa các phòng" emoji="🪪">

Một toà văn phòng có nhiều tầng (**namespace**). **RBAC** là hệ thống **thẻ từ**: thẻ của bạn (**ServiceAccount** hoặc user) được gắn với một **danh sách quyền** (**Role**: "được xem hồ sơ tầng 3") qua một **tờ giấy uỷ quyền** (**RoleBinding**). Không có trong danh sách = cửa không mở.

Nhưng thẻ từ chỉ kiểm soát việc **ra lệnh cho ban quản lý** (gọi Kubernetes API). Nhân viên các phòng vẫn **nói chuyện qua lại được** với nhau qua mạng nội bộ. **NetworkPolicy** là **tường ngăn và cửa có khoá**: "chỉ phòng Kế toán (api) được vào kho tiền (postgres)".

Khi có chuyện, bạn là **bác sĩ trực**: không đoán bệnh, mà khám theo quy trình — xem triệu chứng (`get`), đọc bệnh án (`describe`), hỏi bệnh nhân (`logs`), rồi mới chữa.

</Eli5>

## Vì sao DevOps cần phần này?

Mặc định Kubernetes rất "thoáng": pod nào cũng gọi được pod nào, và ai có kubeconfig admin là toàn quyền. Một pod bị chiếm quyền có thể đi ngang khắp cluster. RBAC + NetworkPolicy là **least privilege** (M01, M06) áp dụng vào Kubernetes. Còn troubleshooting là phần chiếm tỉ trọng lớn nhất trong kỳ thi CKA — và trong ca trực on-call thật.

### RBAC: 4 object

| Object | Phạm vi | Ví von |
|---|---|---|
| `Role` | 1 namespace | Danh sách quyền trong một tầng |
| `ClusterRole` | Toàn cluster (hoặc tái sử dụng ở nhiều namespace) | Danh sách quyền mẫu dùng chung |
| `RoleBinding` | 1 namespace | Gắn Role/ClusterRole cho ai đó *trong tầng này* |
| `ClusterRoleBinding` | Toàn cluster | Gắn ClusterRole cho ai đó *ở mọi tầng* — cẩn thận! |

Chủ thể (subject): `User`, `Group` (đến từ hệ thống xác thực bên ngoài, ví dụ IAM trên EKS) và `ServiceAccount` (danh tính cho pod).

```yaml title="pod-reader-rbac.yaml"
apiVersion: v1
kind: ServiceAccount
metadata:
  name: pod-reader
  namespace: shop
---
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  name: pod-reader
  namespace: shop
rules:
  - apiGroups: [""]              # "" = core API group (pods, services…)
    resources: ["pods", "pods/log"]
    verbs: ["get", "list", "watch"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: pod-reader
  namespace: shop
subjects:
  - kind: ServiceAccount
    name: pod-reader
    namespace: shop
roleRef:
  kind: Role
  name: pod-reader
  apiGroup: rbac.authorization.k8s.io
```

RBAC chỉ có **allow**, không có deny. Mặc định không có quyền gì.

### NetworkPolicy

- Cần CNI hỗ trợ (Calico, Cilium, Amazon VPC CNI có bật network policy, kindnet bản mới). CNI không hỗ trợ thì policy **bị bỏ qua trong im lặng**.
- Khi một pod bị **ít nhất một** policy chọn, traffic theo hướng đó chỉ được phép nếu có rule cho phép.
- Nhớ cho phép DNS (UDP/TCP 53 tới CoreDNS) nếu bạn chặn cả egress.

```yaml title="shop-networkpolicies.yaml"
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: default-deny-ingress
  namespace: shop
spec:
  podSelector: {}                # chọn mọi pod trong namespace
  policyTypes: ["Ingress"]       # không có rule ingress nào = chặn hết
---
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: allow-api-to-postgres
  namespace: shop
spec:
  podSelector:
    matchLabels:
      app: postgres
  policyTypes: ["Ingress"]
  ingress:
    - from:
        - podSelector:
            matchLabels:
              app: api
      ports:
        - protocol: TCP
          port: 5432
```

### Quy trình troubleshooting

```bash
kubectl get pods -n shop -o wide                 # 1. Trạng thái, restarts, node
kubectl describe pod <pod> -n shop               # 2. Events ở cuối — đọc từ dưới lên
kubectl logs <pod> -n shop -c <container> --previous   # 3. Log lần chạy bị crash
kubectl get events -n shop --sort-by=.lastTimestamp    # 4. Dòng thời gian của cả namespace
kubectl exec -it <pod> -n shop -- sh             # 5. Vào trong kiểm tra env, DNS, kết nối
kubectl debug -it <pod> --image=busybox:1.36 --target=<container>  # 6. Image distroless không có shell
kubectl describe node <node>                     # 7. Pressure, taints, allocatable
```

| Trạng thái | Nghĩa là | Lệnh đầu tiên |
|---|---|---|
| `Pending` | Chưa xếp được node | `describe pod` → FailedScheduling |
| `ContainerCreating` kéo dài | Đang gắn volume / cấp IP lỗi | `describe pod` → FailedMount |
| `ImagePullBackOff` / `ErrImagePull` | Không kéo được image | `describe pod` → tên image, quyền registry |
| `CreateContainerConfigError` | Thiếu Secret/ConfigMap | `describe pod` |
| `CrashLoopBackOff` | Start rồi chết liên tục | `logs --previous` |
| `OOMKilled` | Vượt memory limit | `describe pod` → Last State |
| `Running` nhưng `0/1` | readinessProbe fail | `describe pod` → Readiness probe failed |

</Technical>

<Callout type="mistake">

**Gán `cluster-admin` cho ServiceAccount của app "cho nhanh".** Pod đó bị khai thác (RCE) là kẻ tấn công đọc được mọi Secret trong cluster. Chỉ cấp đúng verbs/resources cần thiết, và đặt `automountServiceAccountToken: false` cho pod không cần gọi Kubernetes API.

</Callout>

<Callout type="tip" title="Mẹo tốc độ cho CKA">

`alias k=kubectl`, `export do="--dry-run=client -o yaml"` rồi `k create role pod-reader --verb=get,list --resource=pods $do`. Đừng gõ YAML RBAC từ đầu — sinh bằng lệnh rồi sửa.

</Callout>
