<Eli5 title="Secrets Manager giống két sắt khách sạn có thợ đổi mã định kỳ" emoji="🔐">

Dán mật khẩu database vào file `.env` giống **ghi mã két sắt lên tờ giấy dán ở cửa phòng**: ai đi ngang (Git repo, Docker image, log) cũng đọc được.

**Secrets Manager** là **két sắt của khách sạn**: không ai mang mã theo người. Nhân viên (app) chứng minh mình là ai bằng **thẻ nhân viên** (IAM role), két mới mở. Khách sạn còn có **thợ đổi mã định kỳ** (rotation) — đổi xong tự báo cho nhân viên được phép.

**Parameter Store** giống **bảng thông báo nội bộ có ngăn khoá**: rất hợp để dán cấu hình (log level, URL dịch vụ), có ngăn khoá (SecureString) cho thứ bí mật, rẻ — nhưng không có thợ đổi mã tự động.

</Eli5>

Lộ credentials là nguyên nhân hàng đầu của các vụ bị đào coin trên tài khoản AWS. Nguyên tắc DevOps: **secret không nằm trong code, image, hay biến môi trường dạng plaintext** — app lấy lúc chạy bằng danh tính IAM.

<Technical>

### So sánh nhanh

| | Secrets Manager | SSM Parameter Store |
|---|---|---|
| Mục đích chính | Secret: DB password, API key | Cấu hình + secret đơn giản |
| Kiểu lưu | Chuỗi/JSON, mã hoá KMS | `String`, `StringList`, `SecureString` (KMS) |
| Rotation tự động | **Có** (Lambda hoặc managed rotation, vd RDS) | Không tích hợp |
| Replicate sang region khác | Có | Không tích hợp |
| Chi phí | Theo số secret/tháng + API call | Standard tier miễn phí phần lưu; Advanced tính phí |
| Tổ chức | Tên dạng `prod/shop/db` | Cây phân cấp `/prod/shop/log-level`, `get-parameters-by-path` |

Quy tắc chọn thường dùng: **cần rotation hoặc là credentials DB → Secrets Manager**; cấu hình và secret tĩnh ít quan trọng → Parameter Store.

### Quyền IAM tối thiểu

```json title="app-read-db-secret-policy.json"
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": "secretsmanager:GetSecretValue",
      "Resource": "arn:aws:secretsmanager:ap-southeast-1:123456789012:secret:prod/shop/db-*"
    },
    {
      "Effect": "Allow",
      "Action": "ssm:GetParametersByPath",
      "Resource": "arn:aws:ssm:ap-southeast-1:123456789012:parameter/prod/shop"
    }
  ]
}
```

- ARN secret có hậu tố ngẫu nhiên 6 ký tự → dùng `prod/shop/db-*` trong policy.
- Secret mã hoá bằng **customer managed KMS key** → role cần thêm `kms:Decrypt` trên key đó (và key policy cho phép).

### Cách app nhận secret

- **ECS**: trường `secrets` trong task definition (`valueFrom` là ARN Secrets Manager hoặc Parameter Store) — ECS inject thành biến môi trường lúc container start; *task execution role* cần quyền đọc.
- **EKS**: Secrets Store CSI Driver / External Secrets Operator (học ở phần Kubernetes).
- **Lambda**: gọi SDK và cache, hoặc dùng *AWS Parameters and Secrets Lambda Extension*.
- **RDS** `--manage-master-user-password`: RDS tự tạo và xoay vòng master password trong Secrets Manager.

### Rotation hoạt động thế nào

Secret có nhiều version với nhãn `AWSPENDING`, `AWSCURRENT`, `AWSPREVIOUS`. Rotation tạo mật khẩu mới (PENDING) → đặt lên database → kiểm tra đăng nhập → chuyển nhãn CURRENT sang bản mới. App đang cache bản cũ cần **lấy lại secret khi gặp lỗi xác thực**.

</Technical>

<Callout type="mistake">

**Chuyển secret vào Secrets Manager nhưng vẫn in cả object config ra log lúc khởi động** (hoặc để `--output text` của `get-secret-value` trong CI log). Secret lộ qua CloudWatch Logs cũng nguy hiểm như lộ qua Git. Và nếu secret đã từng bị commit: **đổi mật khẩu ngay**, xoá khỏi lịch sử Git là chưa đủ.

</Callout>

<Callout type="warning">

Biến môi trường ECS/Lambda lấy từ `secrets` chỉ được đọc **lúc container/môi trường khởi động**. Rotation xong, task cũ vẫn giữ mật khẩu cũ tới khi được deploy lại — hoặc app phải tự đọc lại qua SDK.

</Callout>

<Callout type="cost">

Secrets Manager tính phí theo **từng secret mỗi tháng** và theo số API call. Gom các giá trị liên quan vào một secret JSON, cache ở phía app, và dùng Parameter Store Standard cho cấu hình không nhạy cảm.

</Callout>
