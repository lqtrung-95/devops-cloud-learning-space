<Technical>

### Cùng container, khác database — không phải một service mới

Theo spec `taskflow-api` (mục 3 curriculum), service `postgres` đã tồn tại từ B01 với `POSTGRES_USER=taskflow`, `POSTGRES_PASSWORD=taskflow`, `POSTGRES_DB=taskflow`. B07 **không thêm service mới** vào `docker-compose.yml` — chỉ tạo thêm một database khác bên trong đúng instance Postgres đó:

```bash
# Tạo database test — vẫn dùng chung container postgres, chỉ khác tên database
docker compose exec postgres psql -U taskflow -c "CREATE DATABASE taskflow_test"
```

```ini title=".env.test"
TEST_DATABASE_URL=postgres://taskflow:taskflow@postgres:5432/taskflow_test
```

Migrate schema vào database mới này giống hệt cách B04 migrate vào `taskflow`, chỉ đổi biến môi trường:

```bash
DATABASE_URL=$TEST_DATABASE_URL pnpm drizzle-kit migrate
```

### Cạm bẫy: `db` singleton đọc `DATABASE_URL` lúc import

`src/db/client.ts` (B04) đọc `process.env.DATABASE_URL` **ngay khi module được import lần đầu**, rồi giữ nguyên connection đó cho cả process:

```ts title="src/db/client.ts (nhắc lại từ B04)"
const connectionString = process.env.DATABASE_URL ?? "postgres://taskflow:taskflow@postgres:5432/taskflow";
const client = postgres(connectionString, { max: 10 });
export const db = drizzle(client, { schema });
```

Nếu test import `buildApp()` (mà `app.ts` import `db` từ file trên) SAU KHI đã set `process.env.DATABASE_URL = TEST_DATABASE_URL`, mọi thứ ổn. Nhưng nếu import diễn ra trước, `db` đã "đóng băng" với connection string cũ — set biến môi trường sau đó không có tác dụng gì nữa vì module đã chạy xong phần khởi tạo. Đây là lý do file cấu hình môi trường test (`.env.test`, nạp qua `dotenv` hoặc qua biến môi trường của lệnh chạy test) phải có hiệu lực **trước** dòng `import` đầu tiên chạm tới `app.ts`.

### Vì sao không chỉ "xoá hết bảng" trên DB dev sau khi test xong

Có người nghĩ: dùng chung DB dev, rồi cuối mỗi test tự `DELETE FROM users; DELETE FROM projects; ...` cho sạch. Vấn đề: (1) dễ quên xoá đúng thứ tự vì foreign key, (2) nếu test crash giữa chừng, bước dọn dẹp không chạy và rác vẫn còn, (3) hai bộ test chạy song song (CI) trên cùng một DB sẽ xoá dữ liệu của nhau. Một database vật lý riêng loại bỏ cả ba vấn đề bằng thiết kế, không cần kỷ luật "nhớ dọn dẹp".

</Technical>
