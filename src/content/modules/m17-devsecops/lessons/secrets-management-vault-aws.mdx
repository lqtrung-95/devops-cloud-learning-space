<Eli5 title="Secrets manager giống như két sắt khách sạn tự đổi mã mỗi ngày" emoji="🔐">

Cách tệ: viết mật khẩu lên **giấy dán ngay cửa phòng** (hardcode trong code, commit vào Git) — ai đi ngang cũng đọc được, và đổi mật khẩu nghĩa là phải bóc dán lại giấy ở hàng trăm cửa phòng.

Cách tốt: mỗi phòng có **két sắt** (Vault/Secrets Manager). Khách không cầm sẵn chìa khoá két — khách **xuất trình thẻ phòng** (IAM Role/ServiceAccount) tại quầy lễ tân, lễ tân xác nhận đúng khách rồi mới cho mã két **hôm nay**. Ngày mai mã đổi, khách lại xuất trình thẻ để lấy mã mới — không ai cần nhớ, không ai lộ mã cũ mà còn dùng được.

</Eli5>

"Secret nằm trong biến môi trường của Deployment YAML" hoặc tệ hơn "trong file `.env` commit vào Git riêng cho từng môi trường" là lỗi bảo mật phổ biến nhất mà DevOps mới hay mắc. Bài này học cách secret **không bao giờ ở dạng tĩnh, không bao giờ nằm trong Git**.

<Technical>

### Nguyên tắc chung

1. **Không secret nào trong Git** — kể cả file mã hoá nếu key giải mã cũng nằm trong repo.
2. **Pod xin quyền, không tự chứa credential** — dùng IAM Role/ServiceAccount, không copy access key vào Secret.
3. **Rotation tự động** — mật khẩu sống càng ngắn, thiệt hại khi rò rỉ càng nhỏ.
4. **Audit log đầy đủ** — biết ai/cái gì đã đọc secret nào, lúc nào.

### AWS Secrets Manager

- Lưu secret mã hoá bằng **KMS**.
- **Rotation tích hợp sẵn** cho RDS, Redshift, DocumentDB qua Lambda function do AWS cung cấp — chỉ cần bật, không tự viết logic đổi mật khẩu.
- Truy cập qua **IAM policy**, thường kết hợp **External Secrets Operator (ESO)** để đồng bộ vào Kubernetes Secret.

```yaml title="externalsecret-checkout-db.yaml"
apiVersion: external-secrets.io/v1beta1
kind: ExternalSecret
metadata:
  name: checkout-db-credentials
  namespace: shop
spec:
  refreshInterval: 1h
  secretStoreRef:
    name: aws-secrets-manager
    kind: ClusterSecretStore
  target:
    name: checkout-db-credentials   # Kubernetes Secret được tạo ra
  data:
    - secretKey: password
      remoteRef:
        key: prod/checkout/db
        property: password
```

Pod chỉ mount Kubernetes Secret `checkout-db-credentials` như bình thường — ESO lo việc đồng bộ từ AWS Secrets Manager, tự cập nhật khi secret gốc được rotate.

### HashiCorp Vault — dynamic secrets

Khác biệt lớn nhất: Vault có thể **sinh credential MỚI cho từng request** thay vì lưu một mật khẩu cố định rồi rotate định kỳ.

```bash title="Vault dynamic secrets cho PostgreSQL"
vault secrets enable database
vault write database/config/checkout-db \
  plugin_name=postgresql-database-plugin \
  connection_url="postgresql://{{username}}:{{password}}@db.internal:5432/checkout" \
  allowed_roles="checkout-role"

vault write database/roles/checkout-role \
  db_name=checkout-db \
  creation_statements="CREATE ROLE \"{{name}}\" WITH LOGIN PASSWORD '{{password}}' VALID UNTIL '{{expiration}}';" \
  default_ttl="1h" \
  max_ttl="24h"
```

Pod xác thực bằng **Kubernetes Auth Method** (dùng ServiceAccount token, không cần Vault token tĩnh nào lưu sẵn):

```bash
vault auth enable kubernetes
vault write auth/kubernetes/role/checkout-role \
  bound_service_account_names=checkout \
  bound_service_account_namespaces=shop \
  policies=checkout-db-read \
  ttl=1h
```

Mỗi lần pod xin credential, Vault tạo một user Postgres mới sống tối đa 1 giờ rồi tự hết hạn (`VALID UNTIL`) — không có "một mật khẩu dùng chung" nào để rò rỉ.

### Chọn Vault hay AWS Secrets Manager?

| Tiêu chí | AWS Secrets Manager | HashiCorp Vault |
|---|---|---|
| Vận hành | AWS quản lý hoàn toàn | Tự host cluster (hoặc HCP Vault managed) |
| Dynamic secrets | Hạn chế hơn, chủ yếu rotation theo lịch | Mạnh — sinh credential theo yêu cầu, TTL ngắn |
| Multi-cloud | Chỉ AWS | Hỗ trợ đa cloud, đa hệ thống (DB, PKI, SSH) |
| Chi phí | Theo số secret + số lần gọi API | Chi phí vận hành cluster + license (nếu dùng bản Enterprise) |
| Khi nào chọn | Đã 100% trên AWS, muốn ít vận hành | Multi-cloud, cần dynamic secrets sâu, cần PKI/SSH cert nội bộ |

Nhiều tổ chức dùng **cả hai**: Vault cho dynamic database credentials, AWS Secrets Manager cho secret của các managed service AWS thuần tuý.

### Rotation — điều bắt buộc, không phải tuỳ chọn

- Secret tĩnh (API key bên thứ ba không hỗ trợ dynamic): đặt lịch rotation thủ công định kỳ (vd 90 ngày) và **giám sát ngày hết hạn**.
- Secret có hỗ trợ dynamic (database): ưu tiên dynamic secrets/rotation tự động thay vì rotation thủ công.
- Chiến lược "hai user luân phiên" giúp rotation **không downtime**: user A đang active thì tạo/kích hoạt user B trước, chuyển traffic, rồi mới vô hiệu hoá user A.

</Technical>

<Callout type="mistake" title="Secret trong ConfigMap thay vì Secret">

ConfigMap không mã hoá và hiển thị plain text trong `kubectl get configmap -o yaml`. Luôn dùng `Secret` (và tốt hơn là ESO/Vault đồng bộ, không tự tay `kubectl create secret` cho production).

</Callout>

<Callout type="warning" title="IAM Role gắn quá rộng cho ESO">

`ExternalSecret` chỉ nên đọc được đúng path secret nó cần (`prod/checkout/*`), không phải toàn bộ Secrets Manager của tài khoản. Viết IAM policy theo least privilege, giống mọi bài trước trong khoá học.

</Callout>
