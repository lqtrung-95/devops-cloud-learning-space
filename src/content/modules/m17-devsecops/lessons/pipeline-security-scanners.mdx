<Eli5 title="5 trạm kiểm tra giống như 5 trạm kiểm dịch trước khi hàng vào siêu thị" emoji="🚛">

Một xe hàng trước khi vào siêu thị phải qua nhiều trạm: **trạm giấy tờ** (có giấy phép giả không — secret scan), **trạm kiểm tra công thức** (nguyên liệu chế biến có độc không — SAST), **trạm nguồn gốc** (nhà cung cấp có nằm trong danh sách đen không — SCA), **trạm nhà kho** (kho chứa có đúng tiêu chuẩn phòng cháy không — IaC scan), **trạm đóng gói** (bao bì có nhiễm bẩn không — image scan), và cuối cùng **trạm nếm thử tại chỗ** khi hàng đã bày lên kệ thật (DAST).

Mỗi trạm nhìn một góc khác nhau. Bỏ qua một trạm không có nghĩa hàng đó an toàn — chỉ là **chưa ai kiểm tra góc đó**.

</Eli5>

Đây là bài thực hành cốt lõi của DevSecOps: biến 5 loại kiểm tra thành các bước tự động trong CI, sao cho code không an toàn **không thể** tới được production, chứ không phải "hy vọng ai đó nhớ chạy scan bằng tay".

### Bảng tổng hợp 5 loại scanner

| Loại | Công cụ phổ biến | Quét gì | Chạy khi nào |
|---|---|---|---|
| Secret scanning | gitleaks, TruffleHog | Key/token/password lộ trong code & lịch sử Git | Mỗi commit/PR, sớm nhất có thể |
| SAST | Semgrep, CodeQL | Lỗi trong code nguồn của bạn (injection, hardcoded secret) | Mỗi PR |
| SCA | Trivy, Dependabot, Snyk | CVE trong dependency bên thứ ba | Mỗi PR + định kỳ (dependency mới lộ CVE sau) |
| IaC scanning | Checkov, Trivy config, tfsec | Cấu hình sai trong Terraform/Kubernetes manifest | Mỗi PR đổi hạ tầng |
| Image scanning | Trivy, Grype | CVE trong base image + OS packages đã build | Sau khi build image, trước khi push |
| DAST | OWASP ZAP, Burp Suite | Lỗi chỉ lộ khi app đang chạy thật (XSS, header thiếu) | Trên staging, sau khi deploy |

### Pipeline mẫu (GitHub Actions)

```yaml title=".github/workflows/security.yml (rút gọn)"
name: security
on: [pull_request]
jobs:
  secret-scan:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with: { fetch-depth: 0 }
      - name: gitleaks
        run: |
          curl -sSL https://github.com/gitleaks/gitleaks/releases/latest/download/gitleaks_linux_x64.tar.gz | tar xz
          ./gitleaks detect --source . --no-git -v

  sast-sca:
    runs-on: ubuntu-latest
    needs: secret-scan
    steps:
      - uses: actions/checkout@v4
      - name: Semgrep
        run: |
          pip install semgrep
          semgrep --config auto --error
      - name: Trivy filesystem scan (SCA)
        run: |
          curl -sfL https://raw.githubusercontent.com/aquasecurity/trivy/main/contrib/install.sh | sh -s -- -b /usr/local/bin
          trivy fs --severity CRITICAL,HIGH --exit-code 1 .

  iac-scan:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Checkov
        uses: bridgecrewio/checkov-action@master
        with:
          directory: infra/
          quiet: true
          soft_fail: false   # false = fail pipeline khi có finding nghiêm trọng

  build-and-scan-image:
    runs-on: ubuntu-latest
    needs: [sast-sca, iac-scan]
    steps:
      - uses: actions/checkout@v4
      - name: Build image
        run: docker build -t checkout:${{ github.sha }} .
      - name: Trivy image scan
        run: trivy image --severity CRITICAL --exit-code 1 checkout:${{ github.sha }}
```

`soft_fail: false` và `--exit-code 1` là chi tiết dễ quên nhất: mặc định nhiều tool chỉ **in báo cáo** mà không làm build đỏ. Luôn kiểm tra flag "fail on finding" của từng tool.

### DAST — chạy sau khi deploy, không phải trong CI build

```bash title="DAST baseline scan với OWASP ZAP"
docker run --rm -t owasp/zap2docker-stable zap-baseline.py \
  -t https://staging.example.com \
  -r zap-report.html \
  -I  # không fail pipeline ở baseline scan, chỉ báo cáo — dùng -I khi mới bắt đầu áp dụng
```

DAST tấn công app **đang chạy thật** nên chỉ chạy trên staging (không phải production, và không phải chỉ đọc code tĩnh).

### Ưu tiên khắc phục — đừng cố sửa hết cùng lúc

1. **CRITICAL đang bị khai thác được** (ví dụ RCE) → chặn merge ngay.
2. **HIGH có bản vá sẵn** → cập nhật dependency, thường chỉ mất vài phút.
3. **MEDIUM/LOW không có đường khai thác thực tế** → ghi nhận, xử lý theo lịch, có thể suppress có lý do và ngày hết hạn.

Chặn pipeline vì mọi mức độ (kể cả LOW) khiến team tìm cách tắt scanner hoàn toàn — phản tác dụng.

<Callout type="mistake" title="Quét image scan thay cho SCA">

Trivy image scan chỉ thấy dependency **đã build vào image cuối cùng**. Dependency dev-only hoặc lỗ hổng build-time (supply chain attack lúc `npm install`) cần quét filesystem (`trivy fs`) từ sớm, không chỉ quét image.

</Callout>

<Callout type="warning" title="soft_fail / exit-code mặc định">

Nhiều action/tool mặc định KHÔNG fail pipeline dù tìm thấy lỗi nghiêm trọng — chỉ in báo cáo đẹp. Luôn đọc kỹ tài liệu flag fail-on-finding của từng tool bạn thêm vào.

</Callout>
