<Eli5 title="EC2 giống như thuê xe tự lái theo giờ" emoji="🚗">
  **EC2** là dịch vụ **thuê xe tự lái**: chọn dòng xe (instance type — xe 4 chỗ, xe tải, xe đua), lấy xe ra khỏi bãi, trả xe là thôi tính tiền.

  **AMI** là **mẫu xe xuất xưởng**: đã có sẵn động cơ, ghế, radio (OS + phần mềm). Muốn 10 xe giống hệt nhau thì đúc từ cùng một mẫu. **User data** là **tờ ghi chú dán trên vô-lăng** cho lần lái đầu tiên: "chỉnh ghế, cài app bản đồ, đổ đầy xăng".

  **EBS** là **cốp xe tháo rời được**: đồ đạc vẫn còn dù đổi xe (nhưng cốp chỉ lắp vừa xe ở cùng bãi — cùng AZ). **Instance profile** là **thẻ thu phí không dừng** gắn trên xe: qua trạm (gọi API AWS) tự trừ tiền, không cần mang tiền mặt (access key).

  Còn **SSM Session Manager**? Là **tổng đài hỗ trợ từ xa** qua kết nối xe tự gọi về hãng — bạn điều khiển được xe mà không cần mở cửa xe (port 22) cho ai.
</Eli5>

## Vì sao DevOps cần hiểu điều này?

Dù sau này bạn chạy container trên ECS/EKS, bên dưới vẫn là EC2 (hoặc Fargate). Hiểu AMI, user data, instance profile là nền tảng cho launch template, Auto Scaling Group và "immutable infrastructure". Còn Session Manager giúp bỏ hẳn bastion host và SSH key — tiêu chí bắt buộc của lab M07.

<Technical>

### Instance type

Đọc tên `m7g.large`: **m** = họ (general purpose), **7** = thế hệ, **g** = CPU Graviton (ARM), **large** = kích cỡ.

| Họ | Dùng cho | Ví dụ |
|---|---|---|
| **t** | Burstable: tải thấp, thỉnh thoảng tăng vọt (dùng CPU credit) | `t3.micro`, `t4g.small` |
| **m** | Cân bằng CPU/RAM — web app, backend | `m7i.large`, `m7g.large` |
| **c** | Nặng CPU — encode, batch, API tải cao | `c7g.xlarge` |
| **r** | Nặng RAM — cache, database in-memory | `r7i.large` |
| **g/p** | GPU | `g5.xlarge` |

Graviton (ARM) thường rẻ hơn cho cùng hiệu năng, nhưng image/binary phải build cho `arm64`.

### AMI & user data

- AMI là **regional**; muốn dùng ở region khác phải copy. Có thể tự build "golden AMI" (Packer, EC2 Image Builder).
- User data chạy bởi **cloud-init**, quyền root, mặc định **chỉ ở lần boot đầu tiên**. Tối đa 16 KB (trước khi mã hoá base64).

```bash title="user-data.sh"
#!/bin/bash
set -euo pipefail
dnf install -y nginx
echo "<h1>Hello from $(hostname -f)</h1>" > /usr/share/nginx/html/index.html
systemctl enable --now nginx
```

### EBS vs instance store

| | EBS | Instance store |
|---|---|---|
| Bản chất | Ổ đĩa mạng, gắn vào instance | Ổ vật lý trên máy chủ host |
| Stop/terminate | Còn dữ liệu (root volume mặc định bị xoá khi terminate) | **Mất dữ liệu** khi stop/terminate |
| Phạm vi | Một AZ; snapshot lưu ở S3 (regional) | Gắn chết với instance |
| Loại phổ biến | `gp3` (SSD đa dụng), `io2` (IOPS cao) | Cache, buffer tạm |

### Instance profile & IMDSv2

App trên EC2 lấy credential tạm của role qua **Instance Metadata Service** tại `169.254.169.254`. Bật **IMDSv2** (`HttpTokens=required`): mọi request metadata phải có token lấy bằng `PUT` trước — giảm rủi ro SSRF đánh cắp credential.

### SSM Session Manager thay SSH/bastion

| | SSH qua bastion | Session Manager |
|---|---|---|
| Port inbound | 22 trên bastion (và app) | **Không cần** |
| Credential | SSH key phải phân phối/xoay | IAM (có thể bắt MFA qua SSO) |
| Audit | Tự cấu hình | Log phiên ra CloudWatch Logs/S3, CloudTrail ghi ai mở phiên |
| Yêu cầu | Public IP/bastion | SSM Agent + role `AmazonSSMManagedInstanceCore` + đường ra HTTPS tới endpoint SSM (NAT hoặc interface endpoint `ssm`, `ssmmessages`, và `ec2messages` theo tài liệu hiện hành) |

Trên laptop cần cài **Session Manager plugin** cho AWS CLI.

<Callout type="mistake">
  **Instance không hiện trong Session Manager.** Kiểm tra theo thứ tự: (1) role có `AmazonSSMManagedInstanceCore`? (2) instance có đường ra HTTPS 443 — NAT Gateway hoặc interface endpoints? (3) SG outbound có bị chặn? (4) AMI có SSM Agent? Không phải lỗi "port 22 đóng" — Session Manager không dùng port 22.
</Callout>

<Callout type="cost">
  Instance **stopped** không tính phí compute nhưng **EBS volume và Elastic IP vẫn tính phí**. Instance có **public IPv4** cũng tính phí địa chỉ theo giờ. Dọn lab: terminate instance, xoá volume/snapshot thừa, release EIP.
</Callout>

<Callout type="tip">
  Coi EC2 là **gia súc, không phải thú cưng**: đừng SSH vào sửa tay. Mọi thay đổi đi qua AMI/user data/launch template, instance hỏng thì thay bằng cái mới. Session Manager chỉ để debug.
</Callout>
