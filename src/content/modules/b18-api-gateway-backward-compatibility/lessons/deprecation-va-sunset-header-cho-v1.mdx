`/api/v1/tasks` vẫn hoạt động y hệt sau B18 — chỉ thêm hai header báo trước. Bài học này thêm header đó bằng đúng công cụ Fastify đã dùng suốt course: hook, tận dụng encapsulation để header chỉ xuất hiện ở `v1`, không lan sang `v2`.

<Technical>

### Hai header, hai ý nghĩa khác nhau

| Header | Giá trị | Ý nghĩa |
|---|---|---|
| `Deprecation` | HTTP-date (hoặc `true`) | "Version này ĐÃ được đánh dấu deprecated kể từ mốc này" — cảnh báo, KHÔNG phải hành động |
| `Sunset` | HTTP-date | "Version này SẼ ngừng hoạt động vào đúng ngày này" — cam kết một mốc thời gian cụ thể trong tương lai |

Khoảng cách giữa hai mốc là phần quan trọng nhất, quan trọng hơn cả cú pháp header: nó chính là thời gian client được cấp để migrate. `taskflow-api` chọn `Deprecation: 01/09/2026` và `Sunset: 01/03/2027` — cách nhau 6 tháng. Không có con số "đúng" tuyệt đối cho mọi API, nhưng đặt cả hai trùng ngày (hoặc gần nhau) phủ nhận hoàn toàn mục đích của cơ chế: client không còn thời gian phản ứng, khác gì gỡ đột ngột không báo trước.

### Thêm header bằng Fastify hook có phạm vi

Fastify plugin có tính chất **encapsulation**: mọi hook/decorator đăng ký bên trong một plugin chỉ áp dụng cho chính plugin đó và các plugin con được đăng ký bên trong nó — không rò ra ngoài. Đây là lý do hook `onSend` đặt trong plugin `v1` không bao giờ chạy cho route `v2`, dù cả hai cùng sống trong một Fastify instance.

```ts title="src/plugins/v1-deprecation-headers.ts"
import type { FastifyPluginAsync } from "fastify";

const DEPRECATION_DATE = "Tue, 01 Sep 2026 00:00:00 GMT";
const SUNSET_DATE = "Mon, 01 Mar 2027 00:00:00 GMT";

/** Gắn Deprecation/Sunset cho MỌI response gửi ra từ route mà plugin này bao bọc. */
export const v1DeprecationHeaders: FastifyPluginAsync = async (fastify) => {
  fastify.addHook("onSend", async (_request, reply, payload) => {
    reply.header("Deprecation", DEPRECATION_DATE);
    reply.header("Sunset", SUNSET_DATE);
    reply.header("Link", '<https://docs.taskflow-api.example/migrating-to-v2>; rel="deprecation"');
    return payload; // onSend PHẢI trả lại payload, kể cả khi không đổi gì
  });
};
```

```ts title="src/routes/v1/tasks.ts"
import type { FastifyPluginAsync } from "fastify";
import { v1DeprecationHeaders } from "../../plugins/v1-deprecation-headers";
import { listTasksByProject } from "../../services/tasks-service";
import { serializeTaskV1 } from "../../serializers/task-serializer";

export const tasksV1Routes: FastifyPluginAsync = async (fastify) => {
  await fastify.register(v1DeprecationHeaders); // đăng ký TRƯỚC route — áp dụng cho mọi route bên dưới

  fastify.get("/tasks", async (request) => {
    const { projectId } = request.query as { projectId: string };
    const tasks = await listTasksByProject(projectId);
    return { data: tasks.map(serializeTaskV1) };
  });
};
```

Vì `tasksV2Routes` (bài trước) được đăng ký ở `src/app.ts` như một plugin HOÀN TOÀN riêng — không phải plugin con của `tasksV1Routes` — nó không bao giờ thấy `onSend` hook này. Đây không phải trùng hợp: chính encapsulation của Fastify là cơ chế khiến việc "chỉ v1 có header, v2 thì không" trở nên tự nhiên, không cần viết điều kiện `if (version === "v1")` ở bất kỳ đâu.

### Vì sao `onSend` chứ không phải `onRequest`

`onRequest` chạy TRƯỚC khi route handler xử lý — lúc đó chưa có response để gắn header theo ý muốn cuối cùng. `onSend` chạy NGAY TRƯỚC khi response thật sự rời khỏi server, sau khi handler đã set mọi thứ khác — đúng thời điểm để "dán thêm nhãn" vào response mà không ảnh hưởng logic xử lý.

<Callout type="warning" title="Quên `return payload` trong onSend">
  Hook `onSend` PHẢI trả lại `payload` (dù không đổi nội dung). Quên `return payload` khiến Fastify coi như response body bị xoá — client nhận header đúng nhưng body rỗng, một lỗi im lặng rất dễ bị bỏ sót nếu chỉ kiểm tra header bằng `curl -i` mà không xem body.
</Callout>

<Callout type="mistake">
  Đăng ký `v1DeprecationHeaders` như một plugin TOÀN CỤC ở `src/app.ts` (`fastify.register(v1DeprecationHeaders)` không nằm trong prefix nào) thay vì đăng ký bên trong plugin `tasksV1Routes`. Làm vậy hook áp dụng cho MỌI route kể cả `v2` — đúng thứ Deprecation header không nên xuất hiện.
</Callout>
