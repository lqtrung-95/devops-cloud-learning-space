### p50 / p95 / p99 — vì sao không nhìn trung bình

- **p50 (median):** một nửa request nhanh hơn số này. Phản ánh trải nghiệm "điển hình".
- **p95 / p99:** 5% (hoặc 1%) request chậm nhất mất bao lâu. Đây là nơi trải nghiệm tệ thật sự xảy ra — với traffic đủ lớn, "1% chậm" vẫn là hàng nghìn user thật mỗi ngày.
- **Trung bình (average)** dễ bị vài request rất nhanh kéo xuống thấp, che mất đuôi dài đang tệ dần. Không dùng average để kết luận "hệ thống ổn".

### Vì sao đo cả hành trình, không phải một endpoint

Một load test thực tế phải mô phỏng đúng thứ tự người dùng thật làm: **đăng nhập → tạo project → tạo task → comment → upload attachment**. Nếu chỉ bắn tải vào một endpoint đơn lẻ (ví dụ `GET /tasks`), bạn sẽ bỏ lỡ đúng bước gây nghẽn thật — vì nghẽn thường nằm ở bước có đặc điểm khác biệt (CPU-bound, gọi service ngoài, ghi file) chứ không phải bước đơn giản nhất.

### k6 hay autocannon?

| Lựa chọn | Ưu | Nhược | Dùng khi |
|---|---|---|---|
| **k6** | Kịch bản đa bước bằng JS thật (`group`, biến, `Trend` tuỳ chỉnh), threshold pass/fail rõ ràng, output tóm tắt theo từng nhóm | Cần học cú pháp riêng của k6 | Test cả hành trình nhiều bước như `taskflow-api` — đúng nhu cầu của B19 |
| **autocannon** | Cài nhanh qua `npx`, cú pháp tối giản, tốt để bắn tải thô vào một endpoint | Không hỗ trợ kịch bản nhiều bước có state (token, id vừa tạo) tốt bằng k6 | Kiểm tra nhanh throughput của một endpoint đơn lẻ |

Với hành trình 5 bước có phụ thuộc lẫn nhau (cần token sau khi login, cần `projectId` sau khi tạo project...), **k6** phù hợp hơn cho lab này.

### Kịch bản k6 cho hành trình taskflow-api

```js title="load-test/journey.js"
import http from "k6/http";
import { check, group } from "k6";
import { Trend } from "k6/metrics";

const BASE_URL = "http://localhost:8081/api/v1"; // qua nginx gateway (B17/B18)

// Trend riêng cho từng bước để so sánh p95/p99 — không gộp chung một con số.
const loginTrend = new Trend("step_login");
const createProjectTrend = new Trend("step_create_project");
const createTaskTrend = new Trend("step_create_task");
const commentTrend = new Trend("step_comment");
const uploadTrend = new Trend("step_upload");

export const options = {
  stages: [
    { duration: "30s", target: 10 },
    { duration: "1m", target: 50 },
    { duration: "30s", target: 0 },
  ],
  thresholds: {
    step_login: ["p(95)<300"], // sẽ FAIL nếu bottleneck login thật sự tệ như dự đoán
  },
};

export default function journey() {
  let token;

  group("login", () => {
    const res = http.post(`${BASE_URL}/auth/login`, JSON.stringify({ email: "loadtest@taskflow.dev", password: "correct-horse" }), {
      headers: { "Content-Type": "application/json" },
    });
    loginTrend.add(res.timings.duration);
    check(res, { "login 200": (r) => r.status === 200 });
    token = res.json("accessToken");
  });

  const authHeaders = { headers: { Authorization: `Bearer ${token}`, "Content-Type": "application/json" } };
  let projectId, taskId;

  group("create_project", () => {
    const res = http.post(`${BASE_URL}/projects`, JSON.stringify({ name: "Load test project" }), authHeaders);
    createProjectTrend.add(res.timings.duration);
    projectId = res.json("id");
  });

  group("create_task", () => {
    const res = http.post(`${BASE_URL}/projects/${projectId}/tasks`, JSON.stringify({ title: "Load test task" }), authHeaders);
    createTaskTrend.add(res.timings.duration);
    taskId = res.json("id");
  });

  group("comment", () => {
    const res = http.post(`${BASE_URL}/tasks/${taskId}/comments`, JSON.stringify({ body: "note" }), authHeaders);
    commentTrend.add(res.timings.duration);
  });

  group("upload_attachment", () => {
    const res = http.post(`${BASE_URL}/tasks/${taskId}/attachments`, JSON.stringify({ filename: "note.txt", sizeBytes: 1024 }), authHeaders);
    uploadTrend.add(res.timings.duration);
  });
}
```

<Callout type="mistake" title="Kết luận bottleneck chỉ từ một lần chạy">
  Một lần chạy có thể bị nhiễu bởi máy bạn đang làm việc khác cùng lúc. Chạy lại ít nhất 2–3 lần, và luôn so sánh **tương đối giữa các bước trong cùng một lần chạy** (bước nào doãng ra xa nhất khi VU tăng) thay vì tin tuyệt đối vào một con số ms duy nhất.
</Callout>

<Callout type="warning" title="Đừng vá tạm để 'qua' load test">
  Nếu threshold `p(95)<300` fail ở bước login, đừng tăng threshold lên `p(95)<1000` để nó pass — đó là che số liệu, không phải sửa vấn đề. Ghi nhận đúng con số thật, rồi đưa hướng sửa (worker threads cho hash, hoặc scale ngang `api`) vào phần cải tiến của design doc ở lesson sau.
</Callout>
